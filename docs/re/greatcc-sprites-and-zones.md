# Great Chocolate Chase: sprite/object layer, `.anm` assets, characters, zones

Scope: `VSprite` and friends, the `.anm` format as this game uses it, `VObject`/`VAsset` table loading, `VCharacter`/`VPlayer`, the zone graph (`ZoneController`/`Zone`/`ZonePoint`), and the number/text displays. Sources: `re/greatcc/decomp/*.c` (Ghidra of the Mac i386 binary), `re/greatcc/index.tsv`, the binary itself (`otool -tV`, vtables dumped from `__const`), the Mac `assets/` Lua/XML, and a byte parser run over all 198 shipped `.anm` files (scratch: `re/greatcc/scratch/sprites/anm.py`, `vt.py`, `da.py`).

Legend: **F** = read from decompile/disassembly/file bytes (the function or file is cited), **I** = inference, **U** = unknown. Addresses are Mac virtual addresses. "+0xNN" are object offsets in the Mac i386 layout.

Where this overlaps pflib (`TSprite`, `TAnimatedSprite`, `TAnimatedTexture`, `TTextGraphic`, `TClock`) it is the same code as Chocolatier 3; only deltas are recorded here.

## 0. Class hierarchy (F, from the vtables)

```
TSprite -> TAnimatedSprite -> VSprite -> VObject -> VSuspendable -> VCharacter -> VPlayer, VCustomer
                                 |           |            `-> VStation -> VDisplay (and the other stations)
                                 |           +-> VBackground, VTiledObject, VDigit, VCarriable/VChocolate, VButton, VThoughtBubble, ...
                                 `-> VTextSprite
VSpriteEffect -> VAlphaEffect, VGlowEffect, VTintEffect, VWipeEffect, VHoverGlow, VSpriteMove
```

`VSprite` is a scene-graph node, not a thin wrapper: it adds a child list, effects, listeners, mouse events and anchors on top of `TAnimatedSprite`. `VSpriteManager` is a plain object (not a window) owned by a `VSpriteWindow`.

## 1. `.anm` format as this game uses it

### 1.1 Byte layout (F: `TAnimatedTexture::ParseFromANM` 0x9acf4; checked against all 198 files, 0 failures, 0 trailing bytes)

Little-endian. A "string" is `u32 length` + bytes (no terminator). A "tag" is 4 ASCII bytes.

```
"ANIM"
u32   magic1            (read and ignored; always 1)
u32   version           (F: this game's files are ALL version 2; the parser accepts 1 and 2)
string buildPath        (stored; never used again; e.g. "C:\Projects\PlayFirst\ChocolateShop\anim\...\walk_front.xml")
string sourcePattern    (stored; never used again; e.g. ".\*" or ".\background*")
"IMGN"
u32 a, b, c, d          (stored at +0x2c..+0x38 of the texture's private data object; values vary by file: (273,266,0,0) in walk_front, (0,0,0,0) in sauce_base and ingred_base;
                         F: write-only. Only the parsers (`ParseFromANM`, and `ParseFromXML` from attributes of its image node) and the constructor touch them; nothing in `TAnimatedTexture`, `TAnimatedSprite` or the draw path reads them)
[ version == 1 only: 4 more u32 (skipped; the old xform sentinels) ]
string imageName        (e.g. "walk_front.jpg" or a .png)
string maskName         ("" in 36 files, otherwise e.g. "walk_front.mask.png")
"FRMS"
u32 frameCount
  per frame:
    i32 regX, i32 regY                  (registration point inside the frame rectangle; negative values occur)
    u32 srcX, srcY, srcW, srcH          (pixel rectangle in the sheet image)
    [ version > 1 ] f32 scale           (default 1.0; non-1.0 only in machines/sauce/sauce_base.anm frame 27 = 0.5 and ui/upsell/anim_puff.anm frames 3-5 = 0.75, 0.5, 0.25 (0-based; the 198 files above are the ones under anim/, the install has 250 `.anm` in all); multiplies the draw alpha, see 1.5)
    6 x u32/f32 xform                   (default -10000000.0 sentinel in word 0 = none. Real values only in machines/sauce/sauce_base.anm frames 27-30 and ui/upsell/anim_puff.anm frames 3-5 (identity 1,0,0,1,0,0)
                                         and machines/ingredient/ingred_base.anm frames 3-5 (1,0,0,1,tx,ty) with (tx,ty) = (-10,-17), (-16,-27), (-15,-14); every other frame is all-sentinel)
    string frameName                    (the artist's source file, e.g. "dress0001.png"; kept, not otherwise used)
    u32 anchorCount
      per anchor: i32 x, i32 y, string name     (stored unsigned, used as signed)
[ "SCRP" string luaText ]               (113/198 files; if absent, SetDefaultScript builds the default script)
```

Differences from the version 1 layout and from our reader `src/gfx/AnmSheet.cpp` (F):
* Version 1 files: the header's second u32 is a count-like value we ignore, IMGN has 8 u32 and frames have 12 u32. Here the second u32 is the **format version = 2**; IMGN has only **4 u32** (the extra sentinel group exists only for version 1), and each frame record has **13 numeric words**: `regX regY srcX srcY srcW srcH scale xform[6]`. Our reader hard-requires the first u32 (=1) and then reads 8 + 12, so every GREATCC file would mis-parse. It needs a version switch (the first u32 is always 1; branch on the second).
* The mask string is non-empty in 162/198 files (version 1: always empty).
* Anchors are heavily used: 44 files; names `bubble_single` (341 frames), `righthand`/`lefthand` (225 each, the walk sheets), `chocolate`, `money`, `bottle`, `bucket`, `sauce`, `menu`, `thought`, `chocolate1`, `chocolate2`.
* Mac and Windows `anim/` trees are byte-identical (F: `cmp` over every file of `anim/`).

### 1.2 Resolving a file and its textures (F)

* `TAnimatedTexture::ParseAnimation` (0x9b9a4): take the given path; if no such file, try `path + ".xml"`, then `path + ".anm"`. Parse by the extension that is present (`.xml` -> `ParseFromXML`, `.anm` -> `ParseFromANM`). The directory part of the path (up to the last `/` or `\`) is stored as the texture directory (+0x14). Lua passes extension-less names (`file="walk_front"`, `baseDir="anim/"`), so `.anm` is found by the fallback.
* An explicit image name or mask name passed into `TAnimatedTexture::Get(path, imageOverride, maskOverride)` replaces the ones read from IMGN **only when non-empty**. `VAsset` passes `("", maskKeyOfTheAsset)`.
* `TAnimatedTexture::LoadTextures` (0x995a4): image path = directory + imageName, mask path = directory + maskName; falls back to the bare names if the prefixed file is not found. `TTextureData::LoadFile(image, maskOrNull)` loads PNG/JPEG and, with a mask, merges it as the alpha channel.
* Alpha convention (F for the file format, I for polarity): every `.mask.png` in `anim/` is an 8-bit **grey palette PNG** the same size as its `.jpg` (palette entries have R=G=B), so which channel carries the alpha is irrelevant. White = opaque is assumed (I: mean values 115-174 of 255; our `TextureCache` uses the blue channel and white-opaque, which fits). Windows and Mac masks are the same files.
* Sheets are JPEG + separate mask for the large art (backgrounds, walk cycles); small things (e.g. `anim/customers/*/anim_dollar.png`) are RGBA PNG with no mask.

### 1.3 Animation scripts in `SCRP` (F)

* Plain Lua text, several named functions per file. Counts across the 113 scripted files: `DoAnim` (104), `Blink_happy/neutral/annoyed/angry` (24 each; customer faces), `Reverse` (11), `DoAnim_fast`, `DoTopHalf`/`DoBottomHalf` (idle halves), `DoSkirt`, `DoTorso`, `DoRightArm`, `DoRightArmCarry`, `DoRightArmUpper`, `DoLeftArm...`, `DoFlame`, `DoParrot`, `DoStaff`, `DoDoor`, `DoFront`, `DoCrank`, `DoNeedle`, `DoSteam`, `DoParticles`, `DoSauceFill`, `DoDrinkFill`, `DoDrinkSteam`, `DoAnim_0/1/2`.
* Natives/globals the scripts call (F by scanning all scripts): `frames{...}` (475x), `delay(n)` (375x), `random(a,b)` (206x), `getdelay()` (40x), `playsound(path, loop)` (4x), plus calls to other functions in the same chunk (`Reverse` etc.) and plain `while 1 do ... end` loops. Top-level statements run when the chunk is loaded (e.g. `nextDelay = random(20000,40000)` before `DoParrot`).
* `frames{...}` numbers are **1-based** frame indices into FRMS (I: first frame of `walk_front.anm` is 1; the object tables' `base` is the 0-based resting frame, e.g. `base=8` for the arm whose `DoLeftArm` is `frames{9..24}`). Each listed frame is shown for the current `delay` (ms; the default script uses `delay(60)`). `delay(n)` with n up to 40000 is used as a pause between blinks/parrot calls.
* `VSprite::NewScript` (0x49c3a) runs after `TAnimatedSprite::NewScript` and adds two natives to the sprite's script state: **`getdelay()`** = `VSprite::GetDelay()` (the sprite's `delay` field, default 60) and **`playsound(name, loop)`** = `VSoundManager::PlaySFX(str,bool)`. `random`, `delay`, `frames` etc. come from the pflib animation script (see `docs/re/embedded-lua.md` section 6). A new script state is built each time the texture changes (`VSprite::SetTexture` calls Stop(false), swaps the texture, then NewScript).
* The walk/idle/blink scripts need `getdelay` and `playsound`; ours are bound per sprite by `src/games/greatcc/scene/AnimScriptNatives.cpp`.
* Default script for a file with no `SCRP` (F, `SetDefaultScript` 0x98e5e; our `SpriteSheet::defaultScript` already matches): `function DoAnim() delay(60); frames{1,2,...,N} end`.
* How an animation is selected: `VSprite::Play(name, loop, playChildren, delayMs)` (see 2.7). An empty name means the function `DoAnim`. `VObject::Play` substitutes the object's per-state `play=` function name when the caller passes an empty name (1.4).

### 1.4 Frame timing and anchors (F unless marked)

* Frame advance is driven by the pflib `TAnimatedSprite` task on the sprite's `TClock` (the VSprite stores the clock; every sprite in a `VSpriteWindow` uses the clock of the window's parent modal window, `modal+0x50`). `VSprite::Update` never advances frames itself; it only mirrors `GetCurrentFrame()` into +0x9c and handles loop/finish/delayed-start (2.7).
* Anchors: `TAnimatedTexture::GetAnchorPoint(frame, name, &x, &y)` (0x98d9a) linear-searches the frame's anchor list by exact name; returns the stored integers (false if frame out of range or name missing). I: the offsets are relative to the frame's registration point, because they are fed straight into `SetPosition` of a child that is positioned relative to the parent's origin (the registration point).
* `VSprite::AttachToAnchor(name)` (0x4b34e): stores the name (+0xcc); every `Update` re-applies it: take the parent's (weak, +0xbc) animated texture and **current frame**, look up the anchor; if found, negate x when the parent chain is horizontally flipped and y when vertically flipped (`IsFlipped` ORs up the chain), then `SetPosition(x, y)` on the child. If the anchor is not found the position is left as it is. This is how carried items follow the avatar's hands.

### 1.5 Draw-time use of frame registration, `scale` and `xform` (F: `TAnimatedTexture::DrawSprite(TDrawSpec const&)` 0x9898c, `TTexture::DrawSprite(TDrawSpec const&)` 0x9f23c, `CreateVertsFromRect` 0xd29ae, `TDrawSpec::TDrawSpec` 0x15c4d8)

Draw chain: `VSprite::DoDraw` -> virtual `Draw` (`TAnimatedSprite::Draw` 0xa09c2 first sets the texture's current frame, then `TSprite::Draw`) -> `TAnimatedTexture::DrawSprite(spec)`. `spec` is the sprite's complete transform (its own matrix composed with every parent's, `TDrawSpec::GetRelative`), tint, alpha (spec +0x3c) and flags.

`TAnimatedTexture::DrawSprite(spec)`, for the texture's current frame `f`:
1. Copy the spec. Unless the spec already has the "explicit origin" flag (8), set that flag and set the spec origin to the frame's registration point `(regX, regY)`; with the hflip flag (1) the x origin becomes `W - regX` (W = frame width), with the vflip flag (2) the y origin becomes `H - regY`.
2. **xform:** if `f.xform[0]` is not the sentinel -1e7, build the 3x3 row-vector matrix `X` with rows `(x0, x1, 0)`, `(x2, x3, 0)`, `(x4, x5, 1)` (translation in the third row, like every `TMat3` here) and replace the spec matrix by `X * specMatrix` (`operator*(X, spec)`, argument order read from the call site). With the row-vector convention `v' = v * M` that means: **the xform is applied first, to the frame quad expressed relative to the registration point, and the sprite's own transform (rotation/scale/position, parents included) is applied afterwards.** So `(x4, x5)` is a pixel shift in the sprite's own unscaled space; `x0..x3` a linear part about the registration point.
3. If the frame width is 0 nothing is drawn. Source rect = `(srcX, srcY, srcX+srcW, srcY+srcH)`; if the spec already carries a sub-rect (flag 4) that rect is offset by the frame's source origin and intersected with the frame rect, else the whole frame rect is used.
4. **`scale`:** the spec alpha (spec +0x3c) is multiplied by `f.scale`. It is **not** a geometric scale in this code path: `TTexture::DrawSprite(spec)` passes spec +0x3c to `CreateVertsFromRect`, which converts it to the vertex alpha byte (`(int)(alpha * 255)` clamped to 0..255). The shipped value 0.5 on sauce_base frame 27 therefore draws that frame at half opacity. (I that this is the intended meaning; F that this is what the engine does.)
5. `TTexture::DrawSprite(spec)` builds the quad: top-left corner at `-origin` (origin = the registration point just set; without flag 8 it would be the centre `-(w/2, h/2)`), size = source rect size, flips by swapping vertex pairs, vertices transformed as `corner * matrix`, UVs = source rect / texture size, then the spec's blend mode (if not -1) and draw.

Consequences for an implementation: registration comes only from the per-frame `regX/regY` (never from the IMGN words); bounding boxes (`GetBoundingBox`, `GetAnimationBoundingBox`, hit tests) ignore `scale` and `xform`; the only shipped uses are the half-alpha sauce frame and three ingredient icons nudged by a pure translation.

### 2.3 Transform

* `SetAlpha(a)` clamps to [0,1] and writes the draw-spec alpha. `SetFlip(h, v)` sets flag bits 0 and 1. `SetCurrentFrame(n)` is a no-op when `n` equals +0x9c.
* `UpdateMatrix` (0x49a36): draw-spec matrix := rotation matrix (+0x140) with `TMat3::Scale(sx, sy)` applied: `Multiply2x2` multiplies the 2x2 part (M x diag(sx, sy)) and copies the translation across unscaled, so the translation of a rotation about a point is not scaled; then the translation += (position.x, position.y, 0). `SetRotation(cx, cy, angle)` builds the matrix that rotates by `angle` radians about the point (cx, cy) (translate, rotate, translate back), then calls `UpdateMatrix`. `SetScale(sx, sy)` and `SetPosition(p)` store and call `UpdateMatrix`.
* `GetPositionAbs` composes the parents' relative draw specs up the chain. `TDrawSpec::GetRelative(parent)` (0x15c300; the same composition is inlined in `TSprite::Draw`) gives the child's spec: matrix = own x parent's, **alpha = own x parent's**, **flip bits = own XOR (parent's & 3)**, **blend = the parent's when own is -1** (the default). Tint is not composed.
* Coordinates are screen pixels in the window's space; the manager's draw spec starts at origin (0,0), scale 1, with no translation (F), so a `VSpriteWindow` is expected to sit at the screen origin (I; U for non-origin windows).

### 2.4 Draw order (F)

* `VSpriteManager::Draw` (0x4f0da): `VAssetManager::ClearUsed()`, stable-sort the **top-level** list with `SortByDepth` (ascending `depth` +0xa0; ties: ascending position **y**, so lower on screen draws later/in front), `Begin2d`, draw each visible top-level sprite with `DoDraw(spec, -1)`, `DrawDebug()`, `End2d`, then remember the draw time (+0xdc).
* `VSprite::DoDraw` (0x49db4): fire effect event PreDraw(0x80); draw children with **layer < 0** (list is sorted ascending; stops at the first child with layer >= 0); if `selfVisible`: PreRender(0x200), virtual `Draw(spec, 0)`, PostRender(0x400); `TRenderer::SetBlendMode(0)` (so blend modes never leak into children); draw the remaining children (layer >= 0); fire PostDraw(0x100). Each child gets the parent's relative draw spec with its **blend field (+0x54) overwritten with -1** (the store right after `GetRelative`), so a parent's blend mode applies to its own image only; a child with no mode of its own draws with the renderer's current mode, which is 0 after any sprite's image (e.g. `rewardnotify.lua`: the additive `item` bar, with its icon and circle drawn normally). Invisible children are skipped (so their subtrees are too).
* Children are kept sorted by `SortByLayer` (ascending layer, stable: equal layers keep insertion order) after every `AddChild` and every `SetLayer` (the parent re-sorts immediately).

### 2.5 Hit testing and mouse dispatch (F)

* `VSprite::HitTest(point, parentSpec, alphaThreshold, depth)` (0x4a3f2): only if visible and (`mouse` or `leaf`). First `TAnimatedSprite::HitTest(point, spec, alphaThreshold, 0)` on the sprite's own image; if that fails and `depth != 0`: take the union rectangle of the sprite and all visible descendants (`GetRect(spec, depth)`); if the point is inside it, ask each child (iterated **back to front**, i.e. highest layer first) `HitTest(point, childSpec, alphaThreshold, depth-1)` (`-1` stays nonzero for ever). Every spec argument in this family is the *parent's* spec; each sprite composes its own (`GetRelative`).
* `VSprite::GetRect(spec, depth)` returns `TRect` = (left, top, right, bottom) in **ints** (truncated corner bounds of the four transformed corners). The sprite's own `visible` flag is not read (callers test it); the own image counts only when `selfVisible`; the image-less rectangle is the sentinel (1e7, 1e7, -1e7, -1e7); children are united only when visible.
* `TSprite::HitTest` (0xa45a0, pflib): false without a texture or when invisible; then the rectangle test `left <= x < right`, `top <= y < bottom` on the own rectangle (`GetRect(spec, 0)`, so a sprite with `selfVisible` off never hits); with a negative threshold the rectangle alone decides; otherwise it **renders the sprite into a 4x4 render target** translated so the probed pixel lands at pixel (1,1) (the sprite's `Draw` under the given spec: the texel times the spec's alpha and tint), reads the alpha and returns `threshold <= alpha`. The manager uses threshold **1**, so hit testing is **pixel-accurate against the texture alpha** (the mask), not the bounding box. A text sprite has no texture and is never hit.
* `VSprite::GetChildAt(point, spec, threshold)` (0x4b72c) returns the sprite that should receive the event: iterate children back to front, skipping invisible ones and stopping at the first child with layer < 0; the first child whose own `GetChildAt` returns non-null wins; otherwise, if the sprite is `selfVisible` and its own `HitTest(...,0)` passes, it returns itself; finally the layer < 0 children are tried. Then, if a descendant was found: the manager's trace sprite (+0xf4, only shown by the debug overlay) is set, and **if the found sprite (the result of the child's own `GetChildAt`, not the child itself) has `leaf` set, the container (`this`) is returned instead** (F: the byte read is the result's +0xd7; consistent with `VDisplay`, which clears `leaf` and sets `clickable` on a carriable while it is displayed and does the reverse when it is removed). Otherwise the found sprite is returned. The redirect repeats at each level of the recursion, so a chain of `leaf` sprites climbs until a level whose result is not a leaf; a hit on the sprite's own image is returned as it is (no redirect). `GetChildAt` does not read `mouse`: only `HitTest` does, so a `mouse`-off sprite is skipped but its children are still asked (below the top level).
* `VSpriteManager::DoHitTest(point)` (0x4e248): clears the "mouse dirty" flag, walks the top-level list back to front; for each visible sprite with `mouse` set (a top-level `mouse`-off sprite is never asked, its children with it) it computes `GetRect(spec, -1)` (union of everything under it); if the point is inside it calls `GetChildAt(point, spec, 1)`; the first non-null result that `IsValidSprite` accepts is the new hover target (an invalid result is dropped and the walk goes on to the next sprite). If the target equals the old one: send **Move**(1). Otherwise: send **Leave**(0x10) to the old target, then (when there is a new one) **Enter**(8) and **Move**(1), and set the hover target and reset the hover timer (+0xe8) to 0. **Enter and Leave carry the point (0,0); Move, Down, Up and Drag carry the mouse point minus `(int)GetPosition()` of the sprite** (vtable +0x94 is `GetPosition`, the position relative to its parent, not the absolute one; `VPushPin` and the loaders use the same slot for relative positions). Records the clock time at +0xe0.
* `OnMouseMove(p)` (0x4da9e): stores the point (initially (-10000,-10000)); if a sprite is **pressed** (captured at +0x18): its +0xd4 (inside) flag := its own `HitTest(p, spec, 1, -1)`, and it receives **Drag**(0x20) with the relative point (no hit test runs, so no Enter or Leave); returns true. Otherwise just marks the hover as dirty (+0xed) so `UpdateObjects` re-runs `DoHitTest`, and returns whether there is a hover target *now* (the one from the last hit test, which runs once per frame). A press that comes in the same frame as the move that brought the pointer onto a sprite therefore finds no target.
* `OnMouseDown(p)` (0x4e0c0): if the current hover target (+0x10) is valid (`IsValidSprite`, tested again now): send **Down**(0), capture the hover target as it is after the event (+0x18), return true. Otherwise clear the capture and return false.
* `OnMouseUp(p)` (0x4df4a): if the captured sprite is still valid (tested again; lockdown or a new exclusive set since the press drops the Up): send **Up**(2) with the relative point, return true; the capture is cleared afterwards in every case, false when it was not valid.
* `IsValidSprite(s)`: false for null; if the exclusive set (+0x40) is non-empty **or** lock-down (+0xec) is on, the sprite must be in the exclusive set. `SetLockDown`, `AddExclusiveSprite`, `ClearExclusiveSprites` are used by the tutorial code (`VTutorialManager`, `VTutorialSpider`, `VDisplay::OnArrival` while a tutorial runs, `VWorldMap`): "only these sprites react".
* `VSprite::DoEvent(event, point, spec, int)` (0x4a9c6). Event ids: 0 Down, 1 Move, 2 Up, 4 Click, 8 Enter, 0x10 Leave, 0x20 Drag, 0x40 AnimComplete, 0x80 PreDraw, 0x100 PostDraw, 0x200 PreRender, 0x400 PostRender.
  * Virtual hook: Down -> `OnMouseDown` and then +0xd5=1; Move -> `OnMouseMove`; Up -> `OnMouseUp`, +0xd5=0, **then, if `clickable`, `DoEvent(Click)` immediately** (so the order is: the sprite's Up handler, its Click handler, the Click listeners, then the Up listeners; there is no "pointer still inside" test in the base class; subclasses may read +0xd4); Click -> `OnClick`; Enter -> `OnMouseEnter` and then +0xd4=1 (the handler still sees 0); Leave -> `OnMouseLeave` and then +0xd4=0; Drag -> `OnMouseDrag`; AnimComplete -> `OnAnimComplete(currentAnimName)`; PreRender/PostRender -> the virtual `PreRender/PostRender(spec, int)`.
  * Listeners (mouse events 0x7f mask): each listener in the active set whose "dead" flag (+0xc) is false is called with the sprite (listener vtable: +0 AnimComplete, +4 Click, +8 Enter, +0xc Leave, +0x10 Move, +0x14 Down, +0x18 Up, +0x1c Drag): Down/Move/Up/Drag with the point, Click/Enter/Leave without. `AddListener` inserts into the pending-add set and erases from the pending-remove set, `RemoveListener` the reverse (all three are sets: adding twice keeps one), so the last call in a frame wins; `Update` erases the remove set from the active set first and merges the add set afterwards.
  * Effects (events 0x80..0x400): while the guard flag +0xdd is clear, PreDraw (0x80) and PreRender (0x200) call the sprite's effects in **ascending effect id** order, PostDraw (0x100) and PostRender (0x400) in **descending** id order (so effects nest).
* `UpdateObjects` calls `DoHitTest(lastMouse)` first when the mouse is dirty; after the per-sprite updates it adds this frame's `GetElapsed()` to the hover timer (+0xe8) and calls `OnMouseHover(totalHoverMs)` (vtable +0x74) on the hover target.
* Debug (F): Ctrl+T toggles an asset-status overlay and Ctrl+S an overlay with `x:`/`y:` and `TraceSprite: <name>` (`VSpriteManager::OnKeyDown`/`DrawDebug`, `fonts/myriad_pro.mvec`, 12 pt). `VSprite::DrawRect` draws red debug rectangles.

### 2.6 `VSpriteManager` (F; vtable 0x283ec0)

Fields: +0x10 hover target, +0x18 pressed target, +0x20 top-level list, +0x28 removal set (processed in `UpdateObjects`), +0x40 exclusive set, +0x58 global effect list, +0x60 effect set, +0x78 root `TDrawSpec` (identity), +0xd0/+0xd4 last mouse position, +0xd8 clock, +0xe4 time of last update, +0xe8 hover ms, +0xec lock-down, +0xed mouse-dirty, +0xee soft pause, +0xf0 owning window name.

* `AddObject(s)`: `s.SetManager(this)`, push to the end of the list, apply every global effect to `s`, mark mouse dirty. `RemoveObject`/`RemoveAllObjects` clear the sprite's manager and drop it from the list (RemoveAll also clears hover and pressed). `AddGlobalEffect(e)` (once per effect): adds to the list and applies it to every current object.
* `UpdateObjects()` (0x4dcea) per frame, in this order: (1) if mouse dirty -> `DoHitTest`; (2) remove the sprites queued in the removal set from the list; (3) call `Update(softPause)` on every top-level sprite in list order; (4) `UpdateEffects`; (5) hover timer += `GetElapsed()`, `OnMouseHover(timer)` on the hover target; (6) remember the clock time (+0xe4).
* `UpdateEffects()` (0x4de48): for every effect in the set: keep it if it is non-null, `ShouldDelete()` is false and `OnUpdate(softPause)` returns true; otherwise drop it. Then drop global-list entries that are null or no longer `InProgress()`. (So `OnUpdate` is driven by the manager, once per frame per effect, not per sprite.)
* `SetClock(c)`: a different clock clears the elapsed bookkeeping; the clock is pushed to every top-level sprite. `GetElapsed()` = clock time minus +0xe4 (0 on the first call).
* `FindSpriteByName(name)`: depth-first by sprite (`VSprite::FindSpriteByName` = own name, then children in list order). `ForEachSprite(spider, recurse)` visits top-level sprites with a `VSpriteSpider::Process(sprite)` (return false aborts; `recurse` also runs `ForEachChild`).
* `SoftPause(bool)` (vtable slot +0x30, 0x4d91e) sets +0xee, which `UpdateObjects` passes to every top-level `Update(bool)` (and, for children, `VSprite::Update` forwards it) and to every effect's `OnUpdate(bool)`. Callers (F): `ShopWindow::LevelSetup` (pause **on** for the 1000 ms pre-level phase), `ShopWindow::OnTaskAnimate` (pause **off** when the level starts), `VTutorialStep::Begin` (`step.pause && tutorial.pause`) and `VTutorialStep::End` (off). The flag is a cooperative flag: only the overrides below read it; nothing else is stopped.
  Readers of the flag (F, every `Update(bool)` override in the binary was read):
  | class (`Update`) | what is skipped while the flag is set |
  |---|---|
  | `VSprite` (0x4d416) | nothing is skipped; it only records the time the pause began (+0xa4, set on the first paused update, cleared on the first unpaused one). Sprite scripts, `Play`/delay countdowns, anchors, effects and children all keep running. |
  | `VSuspendable` (0x523a2) | after the pause ends, shifts the suspension start (+0x210) forward so the suspension's elapsed time is the elapsed time at the moment the pause began (needs +0xa4). The expiry test itself is not gated: a suspension (a machine busy timer, a customer reading the menu) whose duration expires while paused still finishes during the pause. |
  | `VCharacter` (0x7e40) / `VPlayer` (0x2ce52) | nothing is skipped. Walking, the move queue, facing, idle animations and the player's turn-around countdown run while paused. (`VPlayer::Update` and `VCharacter::Update` only forward the flag to `VSuspendable::Update`.) |
  | `VCustomer` (0x1132e) | skipped: the patience decay of states 1-3 (`patience -= elapsed * decayRate * patience_decay_modifier * level_customer_decay`) and the arrival-time shift (+0x29c moved forward by the pause length once unpaused). Not skipped: the idle-animation countdown, the "special animation finished" check, the endless-mode money decay timer (a real-clock timestamp test), and all walking. |
  | `VDelivery` (0x17b96, the zeppelin-order customer) | skipped: only the countdown (+0x28c) to the next order. The mood/patience countdown (+0x29c, `-0.001 * elapsed` per update in state 1) and the mood thresholds keep running. |
  | `VChocolate` (0x9f20) | skipped: the decay countdown (+0x254) that fades a chocolate away and counts `decayed_this_level`. |
  | `VDisplay` (0x18c9c) | skipped: the loop that auto-detaches decayed chocolates from the display. |
  | `VMachine` (0x21f22) and `VPress`, `VSauce`, `VDrink`, `VInfuse`, `VStation`, `VConveyor` (`UpdateBeltItems` always runs), `VMachineButton`, `BZeppelin` (`UpdatePosition` always runs), `VBackground`, `VDigit`, `VPlotItem`, `VPlotStep`, `VPushPin`, `VReward`, `VTutorial`, `VTutorialStep` | only forward the flag to the base class; nothing is skipped. (`VThoughtBubble` forwards it to its children.) |
  | effects (`VSpriteEffect::OnUpdate`, `VTintEffect::OnUpdate`; `UpdateEffects` passes the flag) | the flag is ignored; fades, moves and glows keep running. |
  Outside the sprite layer, `ShopWindow::UpdateCustomers` skips customer arrival while the flag is set, and `VShopHud::UpdateHud` stops the level `RTimer` while the flag is set or a tutorial is in effect (so the level clock does not run and `PercentElapsed` does not advance).
  Bottom line for a paused tutorial step: the avatar can still walk (a click on a sprite of the step's exclusive set still queues a move); machines and conveyors keep running their animations and timers (suspensions can expire); seated customers do not lose patience (but zeppelin/delivery customers do); no new customers arrive; the level timer does not run (it also stops during any tutorial step, paused or not).
* `GetParentWindow()`: the child window of the top modal window whose name equals +0xf0.

### 2.7 Lifecycle: `Update`, `Play`, `Stop`, `SetDelay`, copy

* `VSprite::Update(softPaused)` (0x4d416): (a) soft-pause bookkeeping: when paused and +0xa4 is 0 set it to the clock time; when not paused clear it; (b) animation state, only if +0xd0 (current function name) is non-empty: if a delayed start is pending (+0xa8 > 0) subtract `GetElapsed()` and, when it reaches 0, start the animation; else if the sprite is playing and not done: nothing; else (finished): if the loop flag is false call the virtual `OnAnimComplete(name)` (listeners are not told: nothing sends them the 0x40 event) and clear the name, if it is true call `TAnimatedSprite::Stop()` and `TAnimatedSprite::Play(name)` directly, not the virtual `VSprite`/`VObject` ones, so the name and loop flag stay and a `VObject` does not go back to its base frame (a loop restarts from the script's beginning each time it ends); (c) mirror the current frame into +0x9c; (d) if an anchor name is set, re-run `AttachToAnchor` (1.4); (e) collect effects that are null or `ShouldDelete()` or have refcount 0, call `RemovedFromSprite` on them and erase; (f) listener housekeeping: move listeners flagged dead to the remove set, `CleanUpListeners` (erase the remove set from the active set, then merge the add set into it); (g) `Update(softPaused)` on every child in list order; (h) remember the update time (+0x98).
* `GetElapsed()` (0x49bd8): when the last-update time (+0x98) is 0 it is first set to the clock's time, so the first call gives 0; the result is 0 when there is no clock, when the clock is not past the last update, or when the difference is >= 3000 ms (so a long stall never produces a big step).
* `Play(name, loop, playChildren, delayMs)` (0x49ff0): stores `loop`; empty name -> `"DoAnim"`; (re)starts only if the name differs from the current one, or nothing is playing, or the animation is done; with `delayMs > 0` the start is postponed by that many ms (+0xa8) instead; `playChildren` also calls `Play("", loop, true, 0)` on every child (recursively, with the default function).
* `Stop(recursive)`: clears delay, loop flag and name, `TAnimatedSprite::Stop()`, and (if recursive) `Stop(false)` on direct children only (grandchildren are not stopped; `VObject::Stop` then sets the frame to the asset's base frame).
* `SetDelay(ms, recursive)`: stores it, and if a script state exists runs the Lua `delay(ms);` in it; recursive applies to all children. `VPlayer::LoadFromTable` sets 30 ms (so the avatar animates at double rate relative to the 60 ms default).
* `CopyTo(dst)`: copies layer, depth, flags (+0xd7..+0xdb), anchor name, draw spec, rotation matrix, scale, position; a nameless destination is named `<srcName>(copy NN)` using +0x90.
* Parent/child: `AddChild(c)`: removes `c` from its old parent, sets `c`'s weak parent, `SetManager`, `SetClock`, appends and re-sorts by layer, calls the manager's `RecalcMouse()` (sets the mouse-dirty flag so the next update re-runs the hit test; `RemoveChild`, `RemoveObject`, `AddObject`, `AddExclusiveSprite` do the same), and applies this sprite's **propagating** effects (effect flag +0x34) to `c`. `RemoveChild` reverses it. `AddEffect(e)`: effects are keyed by effect id; adding the same effect twice increments a count; `RemoveEffect` decrements and removes at 0; `AddedToSprite`/`RemovedFromSprite` are called; a propagating effect is pushed to all children. `CancelEffects` invokes `RemovedFromSprite` on each effect (it does not call `Stop`) and clears the map. `SetManager(m)` also takes the manager's clock and registers the sprite's effects with the manager (+0x60 set) so they get `OnUpdate`.
* `VSuspendable` (0x52776...): `Suspend(ms)` records the clock time (+0x210), flag +0x218 and duration (+0x214); `SuspendWhilePlaying(sprite)` sets the flag and remembers a sprite (+0x21c). `Update(softPaused)`: after an unpause shifts the suspend start forward by the pause length (2.6); when suspended and (the watched sprite is not playing or is done, or the duration has elapsed) it clears the watch, calls the virtual `OnResume()` (base returns true) and, if that returned true, clears the flag; then notifies tutorial listeners (`VTutorialListener::OnResume`). `Reset` clears everything and notifies once. `VCharacter::IsBusy` includes this flag.

## 3. Effects (`VSpriteEffect` and subclasses)

### 3.1 Base class (F)

Layout: +0xc `inProgress` (default true), +0xd `destroyed`, +0x10 own `TClock` (started in the ctor), +0x28 last-update time, +0x2c sprite refcount (incremented by `AddedToSprite`, decremented by `RemovedFromSprite`), +0x30 id (global counter, orders effects), +0x34 `propagate to children`. Virtuals (vtable 0x2824e0): `AddedToSprite`, `RemovedFromSprite`, `InProgress`, `ShouldDelete` (true if destroyed or refcount <= 0), `Stop` (inProgress=false), `Destroy`, `GetElapsed` (own clock minus +0x28), `OnUpdate` (sets +0x28 := now, returns true), `OnPreRender`, `OnPostRender`, `OnPreDraw`, `OnPostDraw`. So `GetElapsed()` inside a subclass `OnUpdate` is the **time since the previous update** (frame delta) provided the subclass calls the base `OnUpdate` last. Hooks receive the sprite (shared_ptr) and the draw spec.

### 3.2 Subclasses (constructor arguments are what the game passes; F for structure, I where marked)

* **`VAlphaEffect(fadeIn, max, durationMs, startAlpha, delayMs)`** (ctor 0x15ee70; `Create` sets nothing else): `startAlpha < 0` -> 0 for fade-in, 1 for fade-out. `AddedToSprite` sets the sprite's alpha to the start value. Each `OnUpdate`: while `delay > 0` subtract the frame delta; then fade-out: `alpha -= max * dt / duration`, clamped to 0, stays in progress while alpha > 0; fade-in: `alpha += max * dt / duration`, clamped to `max`, in progress while alpha < max. `OnPreRender` writes the current alpha into the sprite's draw-spec alpha; `OnPostRender` marks the effect destroyed once it is no longer in progress. Used e.g. `Create(false, 1.0, ms, -1.0, 0)` (fade out over `ms`) and `Create(true, 1.0, 1000, -1.0, 0)` (fade in 1 s).
* **`VTintEffect(targetIntensity, durationMs, TColor, startIntensity)`** (0x8b746; propagating, `VSpriteEffect(this, true)`): intensity (+0x38) moves toward the target at `|target| * dt / duration` per update; after `Stop()` it ramps to 0 and then destroys itself. `OnPreRender` saves the sprite's tint (first nested tint only, global `mTintCount`) and sets tint := `lerp(savedTint, effectColor, intensity)` (nested tints multiply), alpha component 1; `OnPostRender` restores. Used by the tutorial spotlight (`Create(0.5, 300, color, 0)`).
* **`VGlowEffect(peak, periodMs, cycles, accel)`** (0x176c90): propagating. Draws the sprite a **second time after it** (PostRender) with the sprite's blend mode = 2 (additive) and alpha = the glow intensity, while intensity > 0. While running the time accumulator is in whole ms and `(time / period) & 1` picks rise (even) or fall (odd), the intensity being `(time % period) * peak / period` or `peak` minus that: each `periodMs` is one half wave; `cycles <= 0` runs forever (I: used as 1.0 and -1.0); when it stops it decays linearly by `peak*dt/period` and destroys itself. I: the exact time accumulator also adds a `0.5*accel*dt*dt` term, which looks odd for `accel = 1.0`; only `accel = 0.0` (all but one call site) is safe to treat as pure time (U for `accel != 0`).
* **`VHoverGlow(max, propagate, offsetX, offsetY)`** (0x16aa68; game uses `(0.05..0.25, true, true, true)`): `AddedToSprite` creates a `VHoverListener` and registers it so mouse enter/leave toggles the effect's hover flag. Intensity (+0x3c) rises while hovered at `dt * max / 100` per update up to `max`, and falls the same way when not hovered; the effect only ends when it is stopped and the intensity is 0. `OnPostRender` redraws the sprite **four times** always, once for each (+-1, +-1); the offset flags only decide whether that step is multiplied by 0.5 and applied as a shift on the x and y axes (in the sprite's own space) with additive blend (mode 2) and alpha = intensity, producing a halo.
* **`VWipeEffect(direction, reveal, durationMs)`** (0x16d260; direction 0..3): progress (+0x3c) rises by `dt / duration` to 1. `OnPreDraw` reads the current clip rectangle (saved), computes the sprite's rectangle (`GetRect`), and sets a new clip: direction 0 moves the **top edge down** (`reveal=false`) or the bottom edge (`reveal=true`) by `progress * height`; 1 moves the bottom edge up / top edge; 2 the left edge right / right edge; 3 the right edge left / left edge (I: the pairing is read from the branch table); intersected with the previous clip. `OnPostDraw` restores the clip; when progress reaches 1 the effect ends and is destroyed, and a **wipe-away** (`reveal=false`) also hides the sprite (`SetVisible(false)`).
* **`VSpriteMove(target, durationMs, accel, delayMs)`** (0x16d310): per sprite it records the start position when added (`AddedToSprite`). `OnUpdate`: accumulate the frame deltas; `u = clamp((t - delay)/duration, 0, 1)`; eased `e = u*(1 - accel/2) + accel*u*u/2` (clamped to 1; `accel = 0` is linear). `OnPreDraw` sets the sprite position to `start + (target - start) * e` (I on the sign: the decompile shows a subtraction whose operand order Ghidra lost), and ends/destroys itself when `e` reaches 1. It is the only mover for non-characters; `VObjectWindow` builds one from Lua (4.3).

## 4. Windows and Lua loaders

### 4.1 `VSpriteWindow` / `VObjectWindow` (F)

* `VSpriteWindow` is an `RWindow` that creates a `VSpriteManager` in its ctor (+0xec), names itself `"sprite_window"` and clears the window flag 0x800. It forwards mouse move/down/up (returning the manager's bool = "I consumed it") and key down (always returns 0) to the manager, `Draw` = `RWindow::Draw` then `VSpriteManager::Draw`, `OnNewParent` and `PostChildrenInit` hand the parent modal's clock (`modal+0x50`) to the manager, `SetName` also copies the name into the manager.
* `Start()`: replaces its `RScreenInvalidator` task on the parent modal, then `StartWindowAnimation(0x10, true, true, true)` and `TAnimTask::RunOnDraw(true)`: `OnTaskAnimate` runs `UpdateObjects()` once **per drawn frame** and returns true. `PostChildrenInit` calls `Start()` and stores `this` as the window manager's "current sprite window" (`TWindowManager+0x38`).
* `VObjectWindow::PostChildrenInit` (0x81bbc) after the base: reads the window style table **`objects`**; for each table entry: `VObject::Create("", "", 0)`, `LoadFromTable(entry)`, `Init()`, `AddObject`; each entry's optional table **`effects`** is a list of tables; one whose `type` equals `move` (case-insensitive) creates a `VSpriteMove` with `x`,`y` (default 0), `time` (default **300** ms), `accel` (0.0), `delay` (0) and adds it to the object. Nothing else is recognised.

### 4.2 `VObject` table keys (F: `VObject::LoadFromTable` 0x29db8; names from the string operands)

Lookup uses `VLuaStyle` (shared with other analysts): a key is searched in the table, then in its base `style=` table, then up through parent tables. The last argument of each read is the search depth: `-1` = unlimited ancestors (default), `0` = this table only, `N` = N ancestors. Defaults below are "the object's current value" unless a number is given.

| Key | Meaning | Depth |
|---|---|---|
| `leaf` | bool -> +0xd7 | -1 |
| `visible` | bool -> TSprite visible | -1 |
| `mouse` | bool -> +0xd9 (hit-testable) | -1 |
| `clickable` | bool -> +0xda | -1 |
| `continuous` | bool; if true the object calls `Play("", loop, false, 0)` after `Init` and after every asset switch | -1 |
| `layer` | int -> `SetLayer` (sibling order) | -1 |
| `type` | string stored at +0x194 (a label; "autochild" for children created from `children`) | default |
| `spriteLayer` | int -> depth (+0xa0, the top-level draw order) | 1 |
| `name` | sprite name (used by `FindSpriteByName`, tutorials' `highlight_objects`) | default |
| `anchor` | anchor name (1.4) | default |
| `x`, `y` | position (float, default current) | 0 |
| `vflip`, `hflip` | bools (default false) -> `SetFlip(h, v)` | 0 |
| `blend` | int blend mode -> draw spec | 0 |
| `alpha` | float | 0 |
| `tint` | colour | 0 |
| `rotation` | table `{cx, cy, angleRadians}` -> `SetRotation` | 0 |
| `scale` | table; **only `scale[1]` is read and applied to both axes** (F: both reads in 0x2a5b6..0x2a69f use index 1; shipped data has `{0.96, 1.0}` whose second value is therefore ignored). With the fix switch on (design section 7, F3) `scale[2]`, when present, is the y scale | 0 |
| `assets` | table of `assetName = { {state=..., file=..., ...}, ... }`; each becomes a `VAsset` (4.3); the name is lower-cased | n/a |
| `children` | table of `childName = { <VObject table> }`; created with `VObject::Create(lower-cased childName, "autochild")`, loaded recursively, added as child, stored in the children map by lower-cased key | n/a |
| `text` | table of `textName = { <VTextSprite table> }` (8.3) | n/a |
| `autoAsset`, `autoState` | initial asset/state for `Init` | default "" |
| every **non-table** entry of the object's own table (the ones with a meaning above included; empty keys skipped) | stored as a lower-cased-key string attribute (`GetAttribute(name, default)`/`SetAttribute`), e.g. `upgrade`, `category`, `baseY` | n/a |

Loading is idempotent: the previous assets, children and text sprites are detached first (children are removed from the sprite with `RemoveChild`). The asset map and child maps are `std::map` keyed by the lower-cased string, so **iteration order is alphabetical** (matters for the initial asset below).

Style levels (F: the `assets`, `children` and `text` loops of `VObject::LoadFromTable`, which `GetStyle` the group table and `Adopt` each entry into it): an entry's chain is entry -> its group table -> the object -> the object's own parents. So a plain value in a group table reaches the entries below it (`children = { leaf = true, armtainer = {...} }` in `machine_mixer_style`; a group-level `spriteLayer = -2` in `statics`), and a depth of 1 for `spriteLayer` reaches the group, not the object. For an asset entry the chain is entry -> asset table -> `assets` group -> object, which is what depths 1 (`base`, `play`), 2 (`anim`) and 3 (`layer`, which reaches the object's own `layer`) count. The `children` and `text` group tables are read with depth 0 (own table and its `style` base); the `assets` group with depth -1 (every table around the object: a step of a tutorial takes its panel's art from the tutorial, and the empty `anim_1 = {}` of a location's background takes the background's assets and, unnamed, its name). A table found under a flag's key is not a boolean: an asset *named* `anim` (`assets = { anim = {...} }`, as `options.lua` has) sits in the group where `anim = false` would be looked up, and the lookup goes on past it (our `StyleChain::boolean`); the shipped steam animation depends on it. `name`, `type` and `anchor` use the default (unlimited) depth, so a child without its own `name` reads its parent's.

The tables name files from the install root: Mac data says `baseDir = "assets/anim/iquitos/"`, our asset tree starts below `assets/`, so the loader tries the name as given and then without that prefix.

`VObject` constructor `(name, type, int)`: empty name -> `"object_<type><counter>"`; `type` stored; current state `"default"`; counter `mObjCnt` increments.

### 4.3 `VAsset` (the `assets` entries) (F: `VAsset::LoadFromTable` 0x5c2a)

An asset table is `{ baseDir = "...", {entry}, {entry}, ... }`; `baseDir` (default "", depth -1) is prefixed to every `file` and `mask`. Each entry (a table) defines **one state**:

| Key | Default | Meaning |
|---|---|---|
| `state` | `"default"` (depth 0) | state name |
| `file` | "" (depth 0) | texture path without extension; an entry with an empty file is ignored |
| `mask` | "" (depth 0) | optional alpha mask (passed to `TAnimatedTexture::Get` as the mask override, or to `TTexture::GetMerged` for non-animated) |
| `anim` | **true** (depth 2) | true: load as `TAnimatedTexture` via `VAssetManager::GetAnimatedTexture(file)` then `TAnimatedTexture::Get(file, "", mask)`; false: plain `TTexture` (`VAssetManager::GetTexture`, `TTexture::Get` or `GetMerged` when a mask is given) |
| `regX`, `regY` | unset sentinel (FLT_MIN), depth 1 | override of the registration point for this state (only if either is set) |
| `base` | 0 (depth 1) | resting frame number (0-based) used by `Stop` and when the state is selected |
| `layer` | INT_MIN = "none" (depth 3) | overrides the object's layer when this state is selected |
| `play` | "" (depth 1) | animation function to play for this state (empty = `DoAnim`) |

`GetTexture(state)` falls back to `"default"` if the state is missing. Textures are cached in the asset manager by file name. `PreLoadAsset(state)` / `UnloadAsset(state)` load/drop textures (`VObject::Preload/Unload(asset, state, recurse)`, with the pseudo-names `"all"` and `"unused"`).

### 4.4 `VObject` behaviour (F)

* `SwitchAsset(assetName, state, fallbackState)` (0x28a4e): look up the asset by the name as given, not lower-cased (a missing name clears the current asset and sets a null texture); the asset becomes the current one at once (even when it has neither state, so a later `SwitchState` finds it); pick `state` if the asset has it, else `fallbackState`; if the chosen state exists: apply the regpoint override (if present, flag bit 3), `SetTexture(asset.texture(state))`, `SetCurrentFrame(asset.base(state, currentFrame))`, `SetLayer(asset.layer(state, currentLayer))`, remember the state name. If `continuous`, play. `SwitchState(state, fallback)` re-selects the current asset with a new state. `HasAsset`, `AddAsset`. `AddAssetLeaf(asset, state, layer)` (0x29a4c; null when the object has no such asset) creates a child object of the same `type` (`leaf=true`, sprite layer `layer`) that shares the object's asset and shows `state` (else `default`), kept in the child map under the asset's name, de-duplicated as `name_0`, `name_1`, ... A repeated call adds another child; the earlier ones stay.
* `Init()` (0x2925e): after `VSprite::Init`, selects the starting asset: if an asset was already current, re-select it with its stored state; else `autoAsset`/`autoState`; else the **first asset in alphabetical order** with `autoState` and `"default"` as fallback; if `continuous`, play; then `Init()` every child. `Init` is idempotent.
* `Play(name, loop, children, delay)`: does nothing without a current asset or if that asset state has `anim=false`; an empty `name` becomes the asset's `play` function for the current state (falling back to the `default` state's, then to `DoAnim`).
* `Stop(recursive)`: `VSprite::Stop` then `SetCurrentFrame(asset.base(state))`.
* `Draw`: `VSprite::Draw`, then marks the asset/state as used this frame (`VAsset::SetUsed`) for the asset manager's unload logic.

### 4.5 `VBackground`, `VTiledObject`, `VDigit` loaders

* **`VBackground`** (type "background", default depth **-1000** (0xfffffc18), `mouse=false`): `LoadFromTable` runs the `VObject` loader, then reads two sub-tables of VObject tables (names lower-cased, each `VObject::Create("", "")` + `LoadFromTable` + `AddObject` into the **manager**, not as children): **`statics`** (objects tied to upgrades) and **`anims`** (ungated objects). Non-table keys in those tables (e.g. a group-level `spriteLayer=-2`) are inherited by the entries through the style depth rules. Then it preloads the `background` asset of the state that will be needed (`upgrade2`/`upgrade1`/`default`) depending on whether `kBackground1/2` (category `aesthetic`) are active or available (and endless mode / prelevel). `Init`: the background state is `upgrade2` if upgrade `kBackground2` (category `aesthetic`) is active, else `upgrade1` if `kBackground1` is, else `default`; it `SwitchState`s itself, then for every **static**: reads attributes `category` (default `aesthetic`) and `upgrade` (default ""), asks `VUpgradeManager::IsActive(upgrade, category)`; inactive -> `Stop(true)` and hide; active -> show, `SwitchState(state, "default")` and start a `VStateSpider(state)` over its children. `VBackground::SetManager` moves the statics (not the anims) between managers; `RemoveObjects` removes both. `VBackground::Init` walks only the statics: the anims are loaded and added but never initialised (every shipped `anims` table is empty). `VStateSpider::Process(sprite)`: if the sprite is a `VObject`, `SwitchState(state, "default")`; returns true.
* **`VTiledObject`** (F: `LoadFromTable` 0x547a6, `UpdateDrawData` 0x55406, `Draw` 0x548fa, `GetRect` 0x546b2): keys `x1`, `x2`, `y1`, `y2`, `w`, `h` (ints, default 0, depth 0) then the `VObject` loader. `Init` selects asset `background` state `default` before the base `Init`. It is a **nine-slice that stretches, never tiles**: `x1` = left inset, `x2` = right inset, `y1` = top inset, `y2` = bottom inset (all in texture pixels), `w` x `h` = the size on screen. `SetSize(w,h)` and `SetTexture` rebuild the cached slice data, so the size can change after load (unlike `KSplit9`, which builds its nine sprites once). `GetRect` = sprite position .. position + (w, h). Used by `VRewardNotify`, `VPushPin` (score box) and the tutorial bubble (the shipped table has `x1=68,y1=68,x2=44,y2=46`).
  With texture size `(TW,TH)`: `L = min(x1,TW)`, `T = min(y1,TH)`, `Rs = max(0, TW-x2)`, `Bs = max(0, TH-y2)`, middle scale `sx = (w-x1-x2)/(Rs-L)`, `sy = (h-y1-y2)/(Bs-T)`, middle centre `cx = x1 + (w-x1-x2)/2`, `cy = y1 + (h-y1-y2)/2` (float arithmetic). `Draw` does nothing unless `w > 0`, `h > 0` and a texture exists; each of the nine pieces is skipped when its source rect has non-positive width or height. Source rect (x0,y0,x1,y1) -> destination (the piece is drawn **centred** on the given point, scaled about its centre; the box origin is its top-left):

  | piece | source rect | centre in the box | scale |
  |---|---|---|---|
  | top-left | `(0,0,L,T)` | `(x1/2, y1/2)` | 1 |
  | top-right | `(Rs,0,TW,T)` | `(w - x2/2, y1/2)` | 1 |
  | bottom-left | `(0,Bs,L,TH)` | `(x1/2, h - y2/2)` | 1 |
  | bottom-right | `(Rs,Bs,TW,TH)` | `(w - x2/2, h - y2/2)` | 1 |
  | top edge | `(L,0,Rs,T)` | `(cx, y1/2)` | `(sx, 1)` |
  | bottom edge | `(L,Bs,Rs,TH)` | `(cx, h - y2/2)` | `(sx, 1)` |
  | left edge | `(0,T,L,Bs)` | `(x1/2, cy)` | `(1, sy)` |
  | right edge | `(Rs,T,TW,Bs)` | `(w - x2/2, cy)` | `(1, sy)` |
  | centre | `(L,T,Rs,Bs)` | `(cx, cy)` | `(sx, sy)` |

  Same slice semantics as `KSplit9Image` (`ui` 8.1: `x1/x2/y1/y2` = left/right/top/bottom insets, edges and centre stretched, corners at native size). Differences: the box can be resized at any time; `L`/`T` are clamped to the texture while the corner centres use the raw `x1`/`y1`; edge/centre scales are floats and nothing guards `w < x1 + x2` (negative scale mirrors the piece) or `Rs == L` (division by zero, but then the piece is skipped). After drawing it calls `VAsset::SetUsed(asset name, true)`.

### 4.6 `VButton` (F: `re/greatcc/decomp/VButton.c`)

A `VObject` (type `"vbutton"`, name `"<name>_<id>"`) with `clickable` true from construction. Fields: id (+0x210) and its string form (+0x214), the label `VTextSprite` (+0x218), type (+0x220: 0 push, 1 and 2 toggle), `disabled` (+0x224), `selected` (+0x225), scale (+0x228), `sound` (+0x22c). Asset states: `default`, `over`, `disabled`, `on`, `on_over`; a missing state falls back to the second argument of the switch.

* `LoadFromTable(style)`: `id` (int, own table) and `id` as a string, `type` (own), `scale` (own, default 1; `SetScale(scale, scale)`), `sound` (any depth, default ""); the label is created once (`SetLayer(2)`, added as a child), loaded from the **same style** (so it reads the button's `x`, `y`, `font`, `flags` ... through the style chain), and `SetFlags(5)` forced on it; then `VObject::LoadFromTable`.
* `SwitchAsset(asset, state, fallback)`: `VObject::SwitchAsset`, then, with a label: `rect = GetRect(identity, -1)` (the union of the image and every visible child, the label's own current box included); type 0: label size = rect width x height, label position = (-w/2, -h/2); other types: size (800, h), flags 4, position (w/2, -h/2). The rect includes the label's earlier box, so the first size is larger than the image when the label started elsewhere; the label is centred on the origin either way.
* `OnMouseEnter`/`OnMouseLeave` (only when not pressed and not disabled): `SwitchState(selected ? "on_over" : "over", selected ? "on" : "over")` / `SwitchState(selected ? "on" : "default", "default")`.
* `SetDisabled(d)` (on change): `clickable = !d`; true -> `SwitchState("disabled", "default")`; false -> `SwitchState(selected ? (hovered ? "on_over" : "on") : (hovered ? "over" : "default"), selected ? (hovered ? "over" : "default") : "default")`. `SetSelected(s)` (on change): not hovered -> `SwitchState(s ? "on" : "default", "default")`; hovered -> `SwitchState(s ? "on_over" : "over", s ? "on" : "default")`.
* `OnClick` (unless disabled): types 1 and 2 flip `selected`; a non-empty `sound` plays through `VSoundManager::PlaySFX(sound, loop=0)` (group 1000); then a message `(type 3, sprite name, the sprite manager's parent window)` is posted.
* `VObject::SwitchState(state, fallback)` calls the virtual `SwitchAsset` with the current asset's name and does nothing without a current asset.

## 5. Characters

### 5.1 `VCharacter` (F; base for `VPlayer` and `VCustomer`)

State: +0x224 `moving`, +0x218 (inherited) suspended, +0x225 (another busy flag; never set in the code I read, U), +0x226 `special animation playing`, +0x228 last evaluated heading angle (init `-FLT_MAX`), +0x22c vector of idle objects, +0x238 current idle, +0x240 idle countdown ms, +0x244 facing (init -1), +0x248 facing-dirty, +0x24c walk speed (init 5.0), +0x250 current heading angle (init pi/2), +0x254 previous heading (init pi/2), +0x258 direction vector (normalised), +0x260 final destination point, +0x268 current target point, +0x270 current node (the last point reached), +0x278 start point, +0x280 `ZoneController`, +0x288 **move queue** (`list<ZonePoint>`).

Facing enum (F, from the asset selection): **0 = left** (asset `walkright` hflipped), **1 = right** (`walkright`), **2 = front/down** (`walkfront`), **3 = back/up** (`walkback`). `SetDirection(eFacing)` sets the direction vector to (-1,0), (1,0), (0,1), (0,-1) respectively (screen y grows downward) and sets the dirty flag.

Lua keys (F): everything in 4.2 plus **`startZone`**, **`startPoint`** (`ZoneController::FindPointByName(startZone, startPoint)` -> +0x278; both default ""), and the child names with prefix **`idle_`**: every child whose key starts with `idle_` is collected into the idle list and hidden (`SetVisible(false)`).

Operation:
* `Init()`: reset timers and flags, `SetFacing(2)`, `SetDirection(2)`, current target/node/destination := start point, and place the sprite at that point's (x,y).
* `Update(softPaused)` (0x7e40): if not moving: when not busy and the zone controller's path list is non-empty -> `SetDestination(ZoneController::GetNextPoint())`; otherwise when not busy and the move queue is non-empty -> `GotoNextPoint()`. If moving -> `UpdatePosition()`. Then `UpdateFacing()`, `UpdateIdle()`; then if a special animation finished (`PlaySpecialAnim` set +0x226) -> clear it and `SetDirection(2)`; finally `VSuspendable::Update`. The pop and the start of the trip are one `Update` and the first step comes with the next one (`UpdatePosition` runs only in an `Update` that begins with `moving` set).
* `QueueMovePoint(p)` (0x8842, vtable slot +0x13c): ignores null. If `VTutorialManager::TutorialInEffect()` is true (a tutorial is active and not finished) the point is de-duplicated: with an empty queue it is added only if the character is standing at its destination (current node == final destination) or the final destination differs from `p` (so clicking the point it is already walking to is ignored); with a non-empty queue only if the last queued point differs from `p`. When no tutorial is in effect (the normal case) every point is appended with no de-duplication and no limit. Appends to the **back**. Nothing ever removes entries except `GotoNextPoint` (pop front) and the destructor: `Init`, level start and arrival never clear the queue (F: the only users of the list at +0x288 are the constructor, destructor, `Update`, `GotoNextPoint`, `QueueMovePoint`, `IsPathEmpty`).
* `GotoNextPoint()` (vtable +0x170): if not busy and the queue is non-empty: pop the front and call the virtual `TravelTo` (slot +0x138; `VPlayer::TravelTo` for the player); returns whether it started. Callers: `VCharacter::Update` (not moving, not busy, zone-controller path empty) and `VCharacter::AtDestination`.
* `TravelTo(p)` (base, slot +0x138): destination := p; `ZoneController::AddPath(currentNode, p)`; `SetDestination(GetNextPoint())`.
* **`TravelTo` to the point the character already stands on (F, by tracing `VPlayer::TravelTo` 0x2ccf6 -> `AddPath` -> `SetDestination` -> `AtNode` -> `AtDestination`):** the path built for `start == dest` is `[P, P]` (6.3). `SetDestination(P)` finds the sprite exactly at `P` and calls `AtNode` at once; the list still holds the second `P`, so `AtNode` takes the "more path" branch (current node := target, `SetDestination(P)` again), which calls `AtNode` again with an empty list: `moving` stays false, current node := destination and **`AtDestination` runs immediately, inside the same call** - so `VStation::OnArrival` fires at once, with no walking and no delay. Without a centre table the player calls `SetDestination(P)` directly with the same outcome. Condition: the sprite's position must equal the point exactly; it does after a normal arrival because the last step is clamped to land on the point. Pressing a machine button while standing at that machine therefore dispatches the station's arrival in the same frame the queued move is popped (the pop happens in the next `VCharacter::Update` after the click, since `QueueMovePoint` only appends).
* `SetDestination(p)`: target := p; if not busy or already moving: if the sprite is not exactly at the point set `moving=true`, else call `AtNode` at once.
* `UpdatePosition()` (0x7b64): direction := normalise(target - position) (via `SetDirection(TVec2)`, which does **not** set the dirty flag); `step = (speed + |dir.y| * -0.25) * elapsedMs / 10` pixels; clamp the step vector length to the remaining distance; move; if the position now equals the target exactly (the last step is clamped to land exactly) -> `AtNode`. So vertical movement is up to 6% slower than horizontal at the same `speed`.
* `AtNode()`: if there is no zone controller or its path list is empty: `moving=false`, current node := final destination, call the virtual `AtDestination()`; else current node := target and `SetDestination(GetNextPoint())`.
* `AtDestination()` (base): calls `ZonePoint::OnArrival` on the destination (an empty hook at 0x18fdf0, I) then `GotoNextPoint()`, so queued destinations chain.
* `UpdateFacing()` (0x8430): target angle `atan2(dir.y, dir.x)`; rotate the current angle (+0x250) toward it the short way by **at most `player_turn_speed` radians per Update call** (not scaled by time; `VValueManager` real, default 0.2, shipped value **0.4**); remember the previous angle. With `d = target - angle`: `0 < d < pi` turns by `min(d, speed)`; `-pi < d < 0` by `max(d, -speed)`; `d > pi` turns by `-speed` and `d < -pi` by `+speed`, each wrapped into (-pi, pi]; `d == 0` leaves it; **`d == +-pi` exactly (the front-to-back turn of a station facing) turns by `+speed` when the angle is not above the previous angle and by `-speed` when it is**, so a half turn goes the way the heading was already turning. If `|lastEvaluated - current| > 0.02` or the dirty flag is set, map the angle to a facing and call the virtual `SetFacing`: angle in (60 deg, 120 deg) = **2 front**; in (-45 deg, 60 deg] = **1 right**; >= 120 deg or <= -135 deg = **0 left**; otherwise (-135 deg, -45 deg) = **3 back**. Store the angle, clear dirty.
* `SetFacing(f)` (base): records `f`, switches the object's asset to `walkright`/`walkfront`/`walkback` (state `default`, fallback `default`), sets `SetFlip(f == 0, false)`, then `Stop(true)` if not moving, else `Play("", loop=true, children=false, 0)`.
* `UpdateIdle()`: if busy: reload the countdown from `player_idle_first_cooldown` (VValueManager int, default 0, shipped 3000 ms). Otherwise if the countdown > 0 subtract the elapsed time; when it drops below 1 call `PlayRandomIdleAnim()` and reload from `player_idle_cooldown` (shipped 10000 ms). If an idle is showing and (the character became busy, or the idle animation finished/stopped) -> `StopCurrentIdle()` and `SetDirection(2)`.
* `PlayRandomIdleAnim()`: only if not busy and no idle is showing and the idle list is non-empty: choose uniformly among `idle_*` children with `TPlatform::Rand() % count`, show it (`SetSelfVisible(false)` on the character so its own image is hidden), and `Play("", loop=false, children=true, 0)` on the idle child. `StopCurrentIdle()` shows the character again, stops and hides the idle child.
* `PlaySpecialAnim(asset, loop)`: if the asset exists: set +0x226, switch to that asset state `default`, `Play("", loop, false, 0)`; when it finishes `Update` clears it and the character faces front.
* `IsBusy()` = `moving || suspended(+0x218) || +0x225`.

### 5.2 `VPlayer` (F)

Extra state: +0x290 `baseY` (Lua `baseY`, default 0.0), +0x294 `rangeY` (default 1.0), +0x298 `scaleRange` (default 0.0), +0x29c current scale (init 1.0), +0x2a0 turn-around countdown, +0x2a4 preferred hand (init 2), **+0x2a8 hand slot A, +0x2b0 hand slot B** (`VCarriable` shared pointers). Constructor sets `type = "player_character"` and `mouse = false` (the avatar is not clickable).

Keys read by `VPlayer::LoadFromTable` (0x2e276), then `VCharacter` and `VObject` keys: `baseY`, `rangeY`, `scaleRange`. It first drops anything carried (`DetachObject(2)`, `DetachObject(1)`), reads the keys, sets the walk speed from the value `walkspeed`, and finally `SetDelay(30, true)`.
`Init()` also calls `VObject::Preload("all", "all", false)`.

* **Speed:** `VPlayer::UpdatePosition` (0x2d7d2) re-reads `walkspeed` (VValueManager real, default 5.0, **shipped 4.0**, with upgrade modifiers `+0.2` for `kMovement1` and `+0.2` for `kMovement2`, category `gameplay`; how the manager applies `modify` is U/another doc) into the speed before every step, then runs the base movement. With 4.0 the horizontal speed is 0.4 px per ms of `GetElapsed` (I: assuming the clock is in ms).
* **Perspective scale:** after moving, `scale = (y - baseY) / rangeY * scaleRange + 1.0` is applied to both axes (`SetScale(s, s)`), then `PositionCarriables()`. The shipped player has `baseY=375`, `rangeY=155`, `scaleRange=0.06` (the farther down the screen, the bigger, up to about 6 %).
* **The centre table is absent at level 1:** `HasCenterTable` reads station16's visible flag, and `VDisplay::Init` (the class of station16) sets it to whether `kDisplay1` (category `station`) is active; the upgrade is free from level 2 in Iquitos (*machines* 7), so level 1 has no centre table and every trip is a straight line.
* **Pathfinding use:** `VPlayer::TravelTo` (0x2ccf6): destination := p; **only if the `ShopWindow` exists and `HasCenterTable()` is true** does it run `ZoneController::AddPath(currentNode, p)` and walk the returned node list; otherwise it calls `SetDestination(p)` directly and the avatar walks a **straight line** to the point (ignoring the graph). (`HasCenterTable` belongs to the ShopWindow analysis: I: the table that blocks the middle of the room; the graph has the `station16_*` points around it.)
* **Arrival:** `VPlayer::AtDestination` (0x2cfbe): if a `ShopWindow` exists, `GetStationByZonePoint(destination)` and, if there is a station, call its `OnArrival(player, point)` (vtable +0x144); then `VCharacter::AtDestination` (next queued point). **The destination point is stored before the walk starts, so the station sees the point the player clicked toward.** `GetStationByZonePoint` walks the stations by name (`station01`.. in `std::map` order) and takes the first whose point set holds the point.
* **Facing/animation:** `VPlayer::SetFacing` (0x2d8cc): selects the asset by facing as in the base **but flips horizontally for facing 0 (left) AND facing 3 (back)** (the base only flips left). If the facing equals the stored one the asset switching is skipped, but the tail still runs: `Stop(true)` if not moving, else `Play("", true, false, 0)` and every child that is **not** an `idle_*` one (the arms, the torso: the parts that carry the walk cycle) `Play("", true, false, 0)`. When the facing changes: for every child except the `idle_*` ones, `SwitchAsset(walkX, "default", "default")`, except the four arm children: `left_arm` and `left_arm_upper` use state `carry` when `carryLeft`, `right_arm` and `right_arm_upper` use `carry` when `carryRight`, else `default`, where (mirror = facing is 0 or 3): `carryLeft = (slotB != null && !mirror) || (slotA != null && mirror)` and `carryRight = (slotA != null && !mirror) || (slotB != null && mirror)`: slot A is held on the right arm unless the figure is mirrored, slot B on the other, as `PositionCarriables` places them. Then `PositionCarriables()`. (Whether a child is an `idle_*` one is `str::compare(first five characters, "idle_")`, whose result is `strcmp`-like: zero for equal; every place below that reads "not idle" is a non-zero compare.) Finally the **turn-around countdown**: facing 2 sets it to 0, any other facing loads `player_turnaround_cooldown` (default 1000, shipped **500 ms**).
* `VPlayer::Update`: while the turn-around countdown is > 0 it subtracts the elapsed time and, when it reaches 0 and the player is not busy, calls `SetDirection(2)` (so a standing avatar turns to face front half a second after stopping). It also asks any held `VChocolate` whether it should be dropped (`VChocolate` vtable +0x14c; the test is in the chocolate analysis). Then `VCharacter::Update`.
* `PlayRandomIdleAnim`: with fewer than **2 free hands** it does not idle (it just faces front: `SetDirection(2)`); otherwise the base behaviour, and when an idle child was chosen additionally hides every child that is not an `idle_*` one (the idle child holds the whole figure, so the arms and the torso go). `StopCurrentIdle` is the base behaviour and shows every child that is not an `idle_*` one again.
* **Hands (carry capacity = 2):** `NumHandsFree()` = number of null slots (0..2). `AttachObject(item)`: the item's hand requirement is `item+0x210` (1 or 2); it must be <= free hands. A 2-hand item fills **both** slots with the same object and attaches to the anchor name `"bucket"`; a 1-hand item takes slot A if empty, else slot B. Returns true and re-runs `SetFacing(currentFacing)` (facing reset to -1 first) to refresh the arm assets; returns false if there is no room. `PositionCarriables()` (0x2d0ec): each carried item is re-parented (removed from its old parent, `AddChild` on an arm child) and attached to an anchor: slot A goes to `left_arm`/`"lefthand"` when facing is 0 or 3 (mirrored), else to `right_arm`/`"righthand"`; slot B is the opposite; if the arm child does not exist the item keeps its parent and anchor name. The item's scale is set to `(1 - (playerScale - 1)) - ((baseY + rangeY - y) / rangeY) * scaleRange`, applied to both axes (I: this undoes the avatar's perspective scale so carried items look the same size). A 2-hand item is only positioned once. `DetachObject(hand)` (0x2c6d6): hands 2 or 3 detach slot A, other values slot B (hand 0 means "preferred hand then the other"; I: enum names unknown); the item is removed from the arm child, its scale reset to (1,1), the slot cleared (a 2-hand item clears both), the preferred-hand field toggled, and `SetFacing(currentFacing)` re-run. Returns the item (null if empty).
* **Station click and the move queue (F):** a click on a station reaches `VStation::OnClick` (0x4ff32). It takes the first of the station's stored player points and, for every further point in set order, keeps the one **nearest (Euclidean)** to the player's current position (read through the player's vtable slot **+0x94 = `VSprite::GetPosition`**; strict `<`, so the first point wins ties); the player's own current position is used, not the end of the queue. The station's points are resolved at load by name in the zone `avatar` (a name that is not a point is dropped; a single `playerPoint` string that is not one falls back to the station's own sprite name, which is `station00` at that time; a table entry stores its facing under the point's name, default 2, and the single-string form stores none, so the facing lookup gives the map's default 0, left). It then calls the player's vtable slot **+0x13c = `VCharacter::QueueMovePoint`** (not `TravelTo`; `TravelTo` is slot +0x138 and is only reached through `GotoNextPoint`/`Update`) and increments the game state counter `TotalValidClicks`. If there is no player or the station has no points nothing happens.
  What a click does while the player is walking: **nothing is replaced or cancelled**. The point is appended to the queue; the current trip finishes, `VPlayer::AtDestination` runs the station's `OnArrival` (`VStation::OnArrival(player, point)` via `ShopWindow::GetStationByZonePoint`; it turns the player to the point's facing only when the player's move queue is empty: slot +0x174 is `IsPathEmpty`), then `VCharacter::AtDestination` -> `GotoNextPoint` pops the next point and `VPlayer::TravelTo` starts it (chain). While the player is idle the queued point is popped by the next `VCharacter::Update` (not busy, path empty). The queue is the only mover for the player; `QueueMovePoint` is called by `VStation::OnClick` and by nothing else in the binary (`TravelTo`/`GotoNextPoint` are the internal consumers). Customers do not use it. The queue is never cleared (see `QueueMovePoint` above), so rapid clicks execute in order, each distance measured from the player's position at click time. `IsBusy()` (moving, suspended, or +0x225, which is never set to anything but 0) only delays the pop.
* **Walk animation start/stop (F by trace):** nothing in `VCharacter`/`VPlayer` explicitly starts or stops the walk cycle on departure or arrival; it is driven by `SetFacing` (called by `UpdateFacing` when the heading changes by more than 0.02 rad or `SetDirection(eFacing)` marks it dirty, and by `AttachObject`/`DetachObject`). A trip that ends at a station's point sets the point's facing (`SetDirection(eFacing)`, dirty) inside the same `Update`, before `UpdateFacing`, so the cycle stops in that `Update`; a trip that ends at a point no station owns, or with queued points left, does not set it: the cycle goes on in place until the heading next changes or the 500 ms turn-around countdown ends and sets front.

### 5.3 Shipped player data (F)

Only `locations/iquitos/player.lua` describes a real avatar: `game.lua` assigns **`iquitosPlayer` to every location**. The other five `player.lua` files reference `anim/avatar_front|right|back`, which exist in neither the Mac nor the Windows tree; they are unused. Structure of `iquitosPlayer`: top level `name="avatar"`, `mouse=false`, `x=400,y=300`, `spriteLayer=3`, `baseY/rangeY/scaleRange`, `startZone="avatar"`, `startPoint="station01"`; `assets` `walkfront`/`walkright`/`walkback`, each `{state="default", file="walk_*", play="DoSkirt", base=0}`. Hands are the `lefthand`/`righthand` anchors in the arm frames (e.g. (43,-114) and (-44,-113) on skirt frame 1).

## 6. Zones (F unless marked)

### 6.1 `zones/zones.xml` schema (F: `ZoneController::InitializeZones` 0x653e8)

Root `<zonecontroller>` (matched case-insensitively). Children, in any order:
* `<zone name="...">` containing `<point name x y isentrance isexit/>` (x, y ints via `to_int`; `isentrance`/`isexit` are true only when the text is exactly `1`) and `<connection first second/>` (point names inside the zone). A zone is created or reused by name; reloading clears its connections and pathfinding state. Points are created or reused by name; a reused point keeps its connections only if the zone's were not cleared (they are).
* `<crosszone>` containing `<connection firstzone firstnode secondzone secondnode/>`: permanent (non-temporary) connection between points of different zones (looked up by zone then point name; ignored if either is missing).
* Comments and unknown elements are ignored. The shipped file has two zones: `customers` (6 points `customer01..06`, all `isentrance=1 isexit=1`, no connections) and `avatar` (points `station01..17`, `station16_north/east/south/west`; a ring `station01..15` plus chords and spokes; `station17` shares a position with `station07`); the `<crosszone>` block is commented out. The Windows copy is ZXML-compressed, presumably the same content (U: not decoded here).
* **`zones/layers.xml` is not read by the game.** There is no string `layers.xml` in the binary and nothing opens it; its `Room1..3`/`Xray` zones do not exist in `zones.xml` (leftover from another title). `LayerRequest` (a 5-string record, ctor 0x18f400) exists and `ZoneController` owns an empty `list<LayerRequest*>` (+0x20) but nothing fills it. So draw order of people vs furniture comes only from the sprites' `spriteLayer`/`y` (2.4), not from `layers.xml`.

### 6.2 Data model

* `ZoneController` (created by `ShopWindow`, path `"zones/zones.xml"`; the dev `ShopWindow::Debug` reloads it): +0x10 list of zones (new zones pushed to the **front**), +0x18 the current **path** (list of points), +0x20 layer requests (unused), +0xc `zones_debug` flag (`TSettings` int config `zones_debug`, default 0; 1 enables drawing).
* `Zone`: +0x10 points (**front-insertion**, so iteration is reverse of file order), +0x18 entrance points (`isentrance`), +0x20 exit points (`isexit`). `Zone::AddPoint(x, y, name, isEntrance, isExit)` reuses an existing point of that name (resetting pathfinding and updating coordinates and membership).
* `ZonePoint`: +0x14 x, +0x18 y (ints), +0x1c name, +0x20 weak zone, +0x0c connection list (`ZonePointConnection*`, new connections pushed to the **front**), +0x28 **disabled**, +0x29 visited, +0x2a in-frontier, +0x2c cost (int, -1 = unset), +0x30 predecessor (weak). `ResetPathfinding`: visited=false, frontier=false, cost=-1, predecessor=null. `OnArrival` is virtual (empty).
* `ZonePointConnection`: weak target point, `double length`, `bool temporary`. `Zone::ConnectPoints(a, b, temporary)` adds a connection in **both directions** with length = Euclidean distance of the two int points computed in double. `<connection>` in a zone and `<crosszone>` use `temporary=false`.
* `ZoneController::DisablePoint(zone, point, bool)` sets the disabled flag (the path search ignores disabled points; debug drawing skips them). Who calls it is outside this area (U).

### 6.3 `ZoneController::AddPath(start, dest)` (0x64c2a): Dijkstra, with quirks to copy

1. Clear the path list. Look up both points' zones; reset pathfinding on **all** zones.
2. If the two zones differ, `WeldZones(zoneA, zoneB)`: for every exit point of one zone and every entrance point of the other, add temporary (`temporary=true`) two-way connections (I: direction start-zone exits to destination-zone entrances). After the search `UnweldZones` removes every connection with `temporary == true` whose far end lies in a different zone than its owner's. (No shipped data connects zones, so this path is dormant.)
3. Start node: cost 0, visited. Loop: for every connection of the current node (in the connection list's order, i.e. newest first), take the neighbour; skip it if disabled or visited; if it is not yet in the frontier, **push it to the front** of the frontier list and mark it; relax: if its cost is unset, or `(double)neighbour.cost > (double)current.cost + edgeLength`, set `neighbour.cost = (int)edgeLength + current.cost` (**the stored cost uses the edge length truncated to int; the comparison uses the exact double**) and `neighbour.predecessor = current`.
4. Next current node = the unvisited frontier node with the smallest cost (scan from the front, strict `<`, so on ties the **most recently discovered** node wins); mark it visited. Repeat until the frontier has no unvisited node. The search does **not** stop when it reaches the destination.
5. Build the path: `push_back(dest)`, then `cur = dest` and while `cur` is non-null and not `start`: `push_front(cur); cur = cur.predecessor`; finally `push_front(cur)` if non-null (this is the start node). **The destination therefore appears twice at the end** (`[start, ..., dest, dest]`); consumers tolerate it (the last hop is a zero-length move that triggers `AtNode` with an empty list). If the destination is unreachable (all routes through disabled points), `predecessor` is null and the path is `[dest, dest]`: the character walks straight to it.
6. `GetNextPoint()` pops the front (null shared pointer if empty); `IsPathEmpty()`, `ExistsInPath(p)` (linear search, used by the debug draw).

`VPlayer::TravelTo` consumes the first entry (the start node itself: a zero-length hop) and then follows the list through `AtNode`. Speeds are the characters' (5.1/5.2); zones have no speeds, one-way flags or weights besides Euclidean length.

The graph is read once, by the first level load (`OneTimeInit`, `ZoneController::Create`), and a later level load does not reset it, so the route the last avatar was following stays in its path list: a new avatar's first `Update` takes the next node of it (`!moving`, not busy, path not empty) and walks there before anything queued.

### 6.4 Debug drawing (`zones_debug = 1`)

`ZoneController::Draw` (0x647d0, vtable slot 0; called from the shop window): every non-disabled `ZonePoint` is a filled 10x10 square centred on the point (`x-5..x+5`), colour `mNormalPointColor` **(1, 0, 0, 0.75) red**, or `mHighlightPointColor` **(0, 1, 0, 0.75) green** if the point is in the current path; every connection is a 2-vertex line in `mNormalConnectionColor` (**red (1,0,0,0.75)**), the connections between consecutive path points in `mHighlightConnectionColor` (**green (0,1,0,0.75)**); lines to disabled points are skipped. The colour words are RGBA floats read from the static initialisers (0x1c8778, 0x1c87c4...).

## 7. Number and text displays

### 7.1 `VDigit` (F; type string `"digit"`)

An object (`VObject` loader) with one `VTextSprite` child created on load: `VDigit::LoadFromTable` runs the `VObject` loader, creates the text sprite once, loads it from **the same style table** (so the text keys of 8.3 sit directly in the digit's table), sets its text to `"0"`. `SetDigit(n)` clamps `n` to **0..9** and stores it as the target. `Update` (after `VSprite::Update`): if less than **31 ms** have passed since the last tick do nothing; if the displayed value differs from the target step it by **1** toward the target and `SetText("%i")`, record the tick time. The displayed value starts at -1 and the initial text is `"0"`, so after load the digit rolls one step per 31 ms tick from -1 to the target (I: a visible count).

### 7.2 `VDisplay` (F; a station: `VStation(.., 0xb)`)

The display case that holds finished chocolates. Capacity `+0x2b0` = 1, or **2 when upgrade `kDisplay2` (category `station`) is active**; slot vector `+0x2a0` resized to the capacity; count `+0x2ac`; picked item `+0x2b4`. `Init`: if upgrade `kDisplay1` is active it switches to asset `base` and shows itself (`SetVisible(isActive)`), creates a `VDisplayListener`. `AttachCarriable(c)` (0x18d9e): needs a free slot; the first empty index `i` takes it; `AddChild(c)`, `AttachToAnchor("chocolate%i")` with `i+1`, `leaf=false`, `clickable=true`, `layer = capacity`, adds the listener and a `VHoverGlow(0.25, true, true, true)`, registers with `ShopWindow::GetChocolateVendor()->AddDisplayChocolate`, and increments game state counter `DisplayUsed`. `DetachCarriable(c)`: `leaf=true`, `clickable=false`, remove listener, `CancelEffects`, `RemoveDisplayChocolate`, clear the slot, `RemoveChild`. `VDisplayListener::OnClick(sprite)` -> `PickupCarriable(item)`: remember it and fire a Click on the display (so the player walks there via `VStation::OnClick`). `OnArrival(player, point)`: after `VStation::OnArrival`, if a pick-up is pending and the player has enough free hands: detach it and `player->AttachObject`; otherwise, if there is room, take what the player carries (`GetObject<VCarriable>(any hand)`), `DetachObject`, `AttachCarriable`; in a tutorial it also adds the item to the manager's exclusive set. `Update` (not soft-paused): drops every chocolate that reports it should go (`VChocolate` vtable +0x14c).

### 7.3 `VTextSprite` (F; wraps pflib `TTextGraphic`)

A `VSprite` (not a `VObject`) with `mouse=false`, `flags` default **5**, `scale` default 1.0, size 10, default colour from `GetColor`. Keys read by `LoadFromTable` (0x534b4; same style depth rules): `spriteLayer` (depth, default current), `layer`, `name`, **`label`** (the text: a string-table key, or, when it starts with `#`, the literal text after the `#`), `scale`, `w`, `h` (text box size; box origin 0,0), `x`, `y` (position), `bold`, `italic` (bools), `margin` = `{m1, m2, m3, m4}` stored as the rectangle (m1, m2, m1+m3, m2+m4): the first two are the left and top insets, the other two widths of the rectangle that the left and top start (F, `VTextSprite::LoadFromTable` 0x534b4), `flags` (uint, the `TTextGraphic` flags), **`font`** = `{fontName, size, colour}` (colour is a sub-table; shipped example `{edwardian_medium, 18, BlackColor}`), **`outline`** = `{colour, width}`, **`rotation`** = `{cx, cy, angle}`, **`shadow`** = `{dx, dy, colour}` (default shadow colour (0,0,0,0.5)).
* `SetText(s)` wraps the string in markup before handing it to `TTextGraphic`: `<b>..</b>` if bold, `<i>..</i>` if italic, and `<outline color='rrggbb' size=N>..</outline>` if the outline width is non-zero (colour bytes = `(int)(component*255)` in hex).
* `Draw(spec, depth)`: the text origin is the draw spec translation rounded (`+0.5`) plus the margins; when a shadow offset is set the text is first drawn at the shadow offset (rounded) in the shadow colour with alpha scaled by the shadow colour's alpha, then the text colour is restored and the text drawn again. The `TTextGraphic` is created lazily on first use (`GetTextGraphic`), sized `(w - margin.right, h - margin.bottom)` of that rectangle, i.e. `w - (m1+m3)` by `h - (m2+m4)` (F, `GetTextGraphic` 0x531a4; `SetSize` and `GetRect` use the same two fields), so `tutorial_text_style`'s `{40,50,40,35}` leaves a 120 x 100 text area in a 200 x 185 panel, with the rotation applied (`TTextGraphic::SetRotation(angle, cx, cy)`, cx/cy clamped to >= 0). That is the *layout* height, used for wrapping and alignment. The *draw clip* height is the sprite's full `h`: `Draw` builds the rect with top `y+m2` and bottom `y+m2+h`, and `TTextGraphic::Draw` stops at the first line whose bottom (`lineHeight*scale + y`) is below the rect height (a negative clip means none). Centred text taller than the layout area therefore still draws as long as it ends within `h`.
* There is no dedicated "floating text" class in this area. Floating numbers/labels are composed from a `VTextSprite` plus effects (`VSpriteMove`, `VAlphaEffect`); I did not trace a specific caller (U which game events spawn them).

## Choices where the code does not say (I)

* A plain (non-animated) texture is drawn centred on the sprite's position unless the state overrides the registration point (the spec's origin without flag 8 is the centre, 1.5).
* `VWipeEffect` clips by the pairing in `WipeEffect::clipOf`.
* The pixel hit test samples the texel at the centre of the probed pixel (the original renders it into a 4x4 target and reads one pixel; filtering and rounding at the edge are not reproduced), ignores the frame's own `xform` and alpha scale (the rectangle test ignores them in the original too), and takes the sprite's alpha and tint alpha into account (the render does). A `VTiledObject` is hit by its box rectangle (the original draws the nine pieces into the target).
* `VSpriteManager::GetParentWindow` (the message target of `VButton::OnClick`) is looked up in the top modal by the manager's window name; the original's call at that vtable slot is read as `GetParentWindow` from the surrounding code (the neighbour of `SoftPause`, +0x34).
* The station's resolved player points are kept in the order the zone graph made the points (the original's set orders them by the address of their shared-pointer control blocks, which for points allocated one after another follows the file); only a tie between equally distant points depends on it, and the first of them wins.
* `ZoneController::AddPath` welds two zones with the exits of the start point's zone against the entrances of the destination point's zone (the decompile hides which of the two looked-up zones is which; no shipped data connects zones, so the path is dormant). A null start node is not guarded in the original; here it is taken as unreachable.
* The last, clamped step of a walk sets the position to the point itself: the original adds the remaining vector to the position in floats, which equals the point except for a possible last-bit miss that would leave it walking in place.
* A character's idle animation has ended when its sprite script has stopped playing (`IsPlaying` false); `IsDone` is not told apart.
* `VStation::OnClick` and the shop's `OnMouseDown` raise the game-state counters `TotalValidClicks` and `TotalClicks` (`TGameState`); they feed only the analytics and are not kept. `ZoneController::Draw` (`zones_debug`) is not drawn.
* An avatar that has left its sprite manager (a level load replaced it while one of its callbacks ran) ends its arrival chain: it does not start the next queued point.
* `VTextSprite` ignores `rotation` (logged once) and does not scale its layout with the sprite's scale; `shadow` is drawn first at the rounded offset with the shadow colour's alpha.

## Implementation notes for OpenConche

* **`.anm` reader:** `src/gfx/AnmSheet.cpp` must branch on the second u32: version 1 as today; version 2: IMGN with 4 u32, frames with 13 words (`..., scale, xform[6]`); the IMGN words are ignored, registration is per frame, `scale` multiplies draw alpha and `xform` pre-multiplies the sprite matrix about the registration point (1.5). Keep the mask string (162/198 files have one) and apply it with the existing `TextureCache::load(name, mask)` path, which already treats a grey mask as alpha. Resolve names against the `.anm`'s directory, and apply the `file` -> `+".xml"`/`+".anm"` fallback in the asset layer. Per-frame anchors (`lefthand`, `righthand`, `bubble_single`, ...) are needed for carrying and thought bubbles; `SheetFrame` already stores them.
* **Script natives:** `getdelay()` and `playsound(path, loop)` are added per sprite (`scene/AnimScriptNatives.cpp`); `random`, `delay`, `frames` come from `src/sdk/SpriteScript.cpp`. Scripts have many named functions and top-level statements that must run once at load.
* **Sprite tree:** `src/sdk/Sprite` already has layered children, `layer < 0` behind the image, back-to-front hit testing and a TSprite-style pixel hit test; a GREATCC module needs on top: the per-sprite listener/effect lists, the mouse-event state machine of 2.5 (hover/pressed capture, Enter/Leave/Move/Down/Up/Click, click on Up for `clickable` without an inside test), `leaf` redirection, `mouse` filtering, `spriteLayer`+y sort for the top-level list, `AttachToAnchor` re-evaluation every update, and `Play/Stop` semantics of 2.7.
* **Order of operations per frame** (to match behaviour): window Draw (clear used assets, sort, draw, debug) is separate from update; update runs once per drawn frame via the window animation task: hit-test if dirty -> remove queued sprites -> `Update` each top-level sprite (children recursively) -> effects -> hover timer.
* **Zones:** port 6.3 literally (including front-insertion orders, int-truncated costs and the duplicated destination); the pathfinder only matters when the centre table exists, otherwise `VPlayer::TravelTo` walks straight.
* **Constants to keep:** default delay 60 ms (avatar 30), `GetElapsed` clamp 3000 ms, walk step `(speed - 0.25*|dy|) * dtMs / 10`, turn speed per update (not per ms), facing thresholds (60 deg, 120 deg, -45 deg, -135 deg, 0.02 rad re-evaluation), hand capacity 2, digit tick 31 ms, move-effect default 300 ms.
