# Audio: SoundEvent, CADI, music, mixer, pause

Sources, in trust order: Mac decomp `re/mac/decomp/` (`_free/b.c` = BSGSound*, `TSound*.c`, `TSoundManager.c`, `TCadiLite.c`, `TLiteSoundEvent.c`, `TButton.c`, `TSettings.c`, `TPlatformData.c`, `TCustomTextEdit.c`); the Windows exe is not decompiled (`re/win/decomp` is empty), so Windows-only behaviour is from strings, assets and the CAD file; vanilla Lua the original install's `assets/`; Reforged Lua; the shipped files. Companion tables: `audio-events.tsv` (every event -> files). Addresses are Mac VA. Related notes: `api-globals.md` (SoundEvent row), `ledger-and-game-natives.md` s.268, `port-window.md` (ChangeMusic), `particles.md`, `chocolate-factory.md` (event names), `focus-and-display.md`.

## 0. The big picture (facts unless marked)

* Two separate audio paths.
  1. **Direct `TSound`** path (own Ogg decoder, own mixer `TSoundManager`): button click/rollover sounds, `ui_click`, `sfx/firework1..5.ogg`, `sfx/sfx_typing_01..04.ogg`.
  2. **CADI** path: every other `SoundEvent(name)`. The Windows game loads `CadiApi.dll` (`CadiInit`, `CadiEvent`, `CadiShutdown`, strings at 0x5a8458 in the exe) and the data file `assets/cadi/CADI_Choc3_Adam  FINAL.CAD`. The Mac build instead has "CADI-lite" (`TCadiLite`), which reads the text file `assets/cadi/cadilite.spec` (483 lines, 116 event blocks). The engine builds its Mac event table from that file when it is present (`docs/design/mac-audio.md`); the Windows CAD table is used when it is absent.
* All shipped audio is Ogg Vorbis (libVorbis 20040629/20050304). Measured on Reforged files: 113 stereo + 65 mono, all 44100 Hz, nominal 48-112 kbps. `stb_vorbis` is sufficient. No wav/mp3 anywhere. Total: `cadi/audio` 9.9 MB (164 files), `sfx` 308 KB (12 files), `cadi/ui_click.ogg` 5 KB.
* `settings.xml` (vanilla and Reforged) has no audio keys (grep for sound/music/volume/audio/cadi: nothing).

## 1. Lua-facing natives

| Name | Args | Notes |
|---|---|---|
| `SoundEvent(name)` | one string | Registered by `BSGSoundInit` (0x500a) as a Lua global; `BSGSoundShutdown` sets it to nil. Returns nothing: no handle, no loop/volume/pitch args. Missing/unknown names are silent (see s.2). |
| `ToggleSoundMute()` | none | flips pref `soundoff` of the current user; `SetState(kMute)`; `BSGSoundMute(QueryMuteGame())`. Used only by the Options `mutebox` toggle button (`ui/ui_options.lua:46`). |
| `SaveVolumes()` | none | Options window: stores `soundlevel`/`musiclevel`/`ambientlevel` = (int)(slider*1000). Already implemented in the engine. |

There is **no** `StopSound`, `PlayMusic`, `SetMusic`, `CrossFade`, `SetVolume`, `ButtonSound`, `StartMovie`-style audio native. Stop is spelled as events (`Stop_Music`, `Stop_Environments`, `Stop_travel_plane`, ...). `ButtonSound` in the engine is only the name of the engine's own `WindowManager::setSoundHook` (button `sound=`/`rolloversound=` keys).

C++ only (called from native code, not Lua): `BSGSetSoundLevel(float)` 0x4f6a, `BSGSetMusicLevel` 0x4f22, `BSGSetAmbientLevel` 0x4fda, `BSGSoundMute(bool)` 0x4e78, `BSGSoundPause/Unpause` 0x5706/0x56b0, `BSGSoundActivate/Deactivate` 0x55f0/0x5650, `BSGSoundEvent(str)` 0x5166 (also the native entry for message `kSoundEvent` 0x3ea via `TSoundHandler::OnMessage` 0x38ba4).

### `BSGSoundEvent` dispatch (0x5166)
The decompile is `if name == "ui_click" -> cadi/ui_click.ogg; else if find("firework") != 0 -> _CadiEvent(name); else sfx/<name>.ogg`. `str::find` returns the index or 0xffffffff when absent, so the test is "does not start with `firework`" (this corrects `api-globals.md`, which has the branches reversed; the reversed reading cannot be right because the shipped `sfx/` folder holds exactly firework1..5, not the other events). So:
1. `ui_click`: `TSound::Get("cadi/ui_click.ogg", cached=1, group=1000)`, cached in the sound map under `ui_click`, played once.
2. Name starting at index 0 with `firework`: `TSound::Get("sfx/<name>.ogg",1,1000)`, cached by name, played. (Only `firework1..5` exist.)
3. Anything else: `_CadiEvent(name, 0.0)`. This includes `Pause`/`Unpause`, volume events, and the string `cadi/ui_click.ogg` that Reforged passes to `SoundEvent` at 12 sites (it matches no CADI event: silent; those sites are Button style leftovers).
Inference: `TSound::Play(bool)` on these has no loop (`ui_click`, fireworks are one-shots).

## 2. The event table
No XML or text table in the Windows assets. Names live inside the CAD file.

### CAD file format (facts from inspection of the 11,861,719-byte file)
* Binary container (an unidentified small table at the start, not decoded) + Ogg streams + one big XML document + more Ogg. 175 Ogg BOS pages: 136 before the XML (starts at byte 7,442,762), 38-39 after it. The XML (`<?xml ...?><Project>`, 1,449,586 bytes, ends byte 8,892,348) holds 2,363 `PropertySet` records of a SpinSound graph. Types: MixerChannel 542, Repeater 510, LoopBox 358, Envelope 254, Randomizer 199, SampleResource 177, TrackPlayer 107, Mixer 61, RandomSelector 58, Arrangement 36, ArrangementClip 31, others few. Fields used: `Name`, `Parent`, `ChildName`, `Volume`, `SoundList`, Repeater `RepeatsMin/Max`, `IntervalMin/Max`, `Infinite`, Envelope `Attack/Release` (ms), Randomizer `VolumeVaryMin`, LoopBox `ResourceName`, `ResourceLoopEnabled`, `Stream`, Arrangement `Tempo`, `MasterModeFadeTime`, `SourceModeFadeTime`, `TimeLineLoopEnabled`.
* The Ogg payloads are embedded in the CAD. Reforged ships them pre-extracted as `cadi/audio/*.ogg` (164 files; names equal the `ResourceName` basenames with `.wav` -> `.ogg`; e.g. event `positive_haggle` -> file `poitive_haggle.ogg`, `ingredient_match_N` -> `ingredient_match_(N+2).ogg` (N=1..5), `ingredient_match_0` -> `match_ingredient_0.ogg`). **The vanilla installer has only the CAD, no `cadi/audio/`**. The CAD directory is decoded in s.10.9. **A basename is NOT enough to name a CAD resource**: 13 basenames occur twice (7 with different bytes), so file references must be resolved from the project XML `ResourceName` of the node that plays them. `audio-events.tsv` has `resource_path` / `reforged_file` columns for this; see the twin table in s.10.9. Reforged's `Ce_MapMELODICLAYER (2).ogg` and `footsteps_2.ogg` are the second copies.
* Root events (Lua-callable names) are the MixerChannel children of three mutually-grouped mixers: `New Mixer 2` = **Sfx** (60 one-shots/loops), `New Mixer 3` = **Environments** (25, mutual exclusion on), `New Mixer 4` = **Music** (28 arrangements, mutual exclusion on), plus the `Events` mixer: arrangements `Stop Music`, `Stop Sfx`, `Stop Environments`, `Music Volume`, `Sfx Volume`, `Environments Volume`. `audio-events.tsv` lists all of them with resolved files (columns: `files` = main/bed files; `intermittent_files` + `interval_ms` = random sweetener one-shots; `envelope_ms` = attack/release).
* Per-channel gains stored in the CAD: Root mixer channels Sfx 0.806, Music 0.717, Environments 1.423, Master Bus 0.985; individual events carry `Volume` (e.g. `choco_making_game` 1.353, `coffee_making` 1.306, `launch` 0.416, `ingredient_success_*` 0.70-0.77) shown in the tsv column `channel_volume` (empty = 1.0). Volume values above 1 are gains in the CADI mixer.

### Event kinds and semantics
* **Sfx one-shot** (most of 60): channel -> Delay repeater (0-1000 ms interval, 1 repeat; effectively immediate: `Immediate=true`) -> Envelope -> Randomizer -> LoopBox. Plays the file once. Variants are separate event names (`ingredient_success_1..5`, `ingredient_failure_1..8`; the native code builds `ingredient_failure_%lu`, `ingredient_success_%lu`, `ingredient_color_match_%lu`, `ingredient_match_%lu`).
* `launch` (0x416 vol): a random selector over `launch_base_1..3`, `launch_gears_1..2`, `launch_pop_1..5`: one random child per trigger (fact, section 10 Q6).
* **Sfx loops** (stopped by `Stop_*` events): `machine_spin` (2.68 s), `travel_plane` (4.50 s, envelope attack/release 1601 ms), `win_money` (marked loop in CAD). Stop events: `Stop_machine_spin`, `Stop_travel_plane`, `Stop_win_money` (each kills the named clip), `Stop_conveyor_belt_loop` (empty track, no-op).
* **Environments** (25, `cadikey` of ports/buildings): a looping bed (`city`, `waterfront city`, `jungle`, `desert`, `bank`, `market`, `casino_ambience`; 5-6 s files) with envelope fade-in/out 700-2000 ms plus "sweeteners": an infinite repeater that every random `interval_ms` (about 1.1-4.5 s, per event) fires one random one-shot (`seagull1`, `wave1`, `bird*`, `car_by_*`, `dog_bark_2`, ... see tsv) at a randomised volume (Randomizer VolumeVaryMin 0.135-0.255 = inference: volume spread of that size). The Mixer is mutually exclusive: starting an environment stops the previous one; `Stop_Environments` stops it. Starting an event whose channel is already running: Unknown (restart vs ignore).
* **Music** (28 arrangements): see s.3.
* **Volume events** (`Music Volume`, `Sfx Volume`, `Environments Volume`): called as `_CadiEvent(name, level)` with level 0..1 (the slider fraction); each is an arrangement with an automation clip targeting the channel Volume (stored points 0.3125 / 0.4875 / 0.5625, probably editor defaults). The exact function from `level` to gain inside CADI is **Unknown**; assume linear multiply.
* `Pause` / `Unpause`: not in the CAD; the strings are in `CadiApi.dll`, so they are built-in events pausing the whole CADI graph (inference from presence of strings; Mac `procHardcodedEvent` confirms the hard-coded event idea: `<group> Volume` and `Stop <group>`, with `all` allowed for Stop).

What is lost: layered sting-then-map handover with beat-synced fades, the `port_music` intermittent clips, and the unused C3 Gameplay stems (no caller found, so nothing lost today).

## 4. Mixer semantics (TSoundManager, facts)
* Volume of a stream = master (`SetVolume`; 0 on mute, 1.0 on unmute; initial value not checked) x `typeVolume[group]` (map int -> float; **a group never set reads as 0.0** and silences those streams, so `BSGSetSoundLevel` at startup via `SetSoundForCurrentUser` is what turns sound on), clamped to [0,1] in `TSoundStream::SetVolume` (limits at 0x000f05d4/d8 are a clamp pair; values read as 0 and 1, which fits). Linear gain; no dB curve in the native mixer. (CADI internals unknown, probably linear.)
* Groups (`TSound::Get(path, cache, group)`; path may carry `?group=N` which overrides): group **0** = button sounds (`TButton::SetSound` -> `Get(path,1,0)`); **1000** = Sfx (`ui_click`, `sfx/*`, typing); **1001** = Music type (set by `BSGSetMusicLevel`; no `TSound` is in group 1001 in the game data I saw). `BSGSetSoundLevel(x)` sets groups 1000 and 0 and sends CADI `Sfx Volume`; `BSGSetMusicLevel(x)` group 1001 and `Music Volume`; `BSGSetAmbientLevel(x)` only CADI `Environments Volume`.
* Level scale: prefs per user in per mille. Defaults: `soundlevel` 750, `musiclevel` 650 (`TSettings::SetSoundForCurrentUser` 0x35e20 passes 0x2ee/0x28a), `ambientlevel` 500, `soundoff` 0. Float sent = pref/1000. Options sliders are 0..1; stored (int)(v*1000). Applied: at login/`SetCurrentUser`, on slider messages live, on unmute. `BSGSoundMute(true)`: master 0.0 + CADI Music/Sfx/Environments Volume events with 0; `false`: master 1.0 and re-apply stored levels. `CreateNewUser` copies the four prefs from the current user.
* Concurrency: no limit found. `TSound::Play` creates a new `TSoundStream` (+`TSoundInstance`) for every call and registers it in the manager's stream vector; `KillAllSounds(group)` / `TSound::Kill` stop them. Max instances: none (**no cap found**). Pitch/pan variation: none in the native path.
* Data: `TSound::Get(...,cache=1,...)` = fully decoded in memory (non-streaming), `cache=0` streams (`Create(path, stream = !cache)`); Ogg only (`TOggDataSource`).
* Hard-coded event syntax in Mac CADI-lite: `<group> Volume` / `Stop <group>` (also with `_`). The `.spec` event format is the Mac build's (read by `src/audio/CadiLite.cpp`; grammar, shipped content and the compile rules are in `docs/design/mac-audio.md` s.1 and s.2): `:"name"` opens an event, a blank line ends it, and each entry is a quoted call of an earlier event, `play <group> <file> [loop]` or `stop <file>`. A repeated name keeps its first definition. The Windows data uses the CAD instead.

## 5. Focus loss and pause (facts)
* `TPlatformData` window events call `TSoundManager::AppActivate(false)` on deactivate/minimise/display-mode swap and `AppActivate(true)` on activate. Deactivate: every registered `TSoundStream::SystemPause(true)`; activate: `SystemPause(false)` then `UpdateAllVolumes`. This pauses the TSound streams (button clicks, ui_click, fireworks, typing; they are short).
* CADI pause is separate: `BSGSoundDeactivate()` sends event `Pause`; `BSGSoundActivate()` sends `Unpause`; guarded by flags `gSoundPaused` (game pause) and `gSoundDeactivated` so each only fires on a transition and focus changes do not override a game pause. `BSGSoundPause/Unpause` are called by the chocolate and coffee factories' `PauseGame`/`ResumeGame` (ChocolateFactory.c:191/1783, CoffeeFactory.c:200/1518) only. I did not find a caller of `BSGSoundActivate/Deactivate` in the decompile (Mac app delegate, or unused; **Unknown**), but the intent is clear.
* Engine: `World::setForeground` (World.cpp:65) currently logs stub `SoundEvent.Pause/Unpause`. It should call `Audio::setPaused(!fg)` which pauses all live voices (SDL3: `SDL_PauseAudioStreamDevice` on the device; or stop pulling), keep a separate `gamePaused` flag (factory pause), and on foreground unpause only if not game-paused.

## 7. What the engine must implement (ordered)
1. **Audio device + decode (stb_vorbis):** decode `.ogg` fully to float/int16 and cache (files are tiny except music 0.3-0.5 MB). Open SDL3 audio device 44100 stereo; mix N voices in a callback (no cap needed; 16-32 is plenty). Linear gains, clamp 0..1.
2. **(a) SFX one-shots:** `SoundEvent(name)`: resolve via the event table (audio-events.tsv converted to engine data): `ui_click`, `firework*` and Button paths direct; kind `oneshot` plays its file; `oneshot_layered` (`launch`) plays one random pick per layer (inference); never error on unknown names. Events at channel volume (apply `channel_volume` as gain, may exceed 1 only for music).
3. **(b) Looping SFX with stop:** kinds `loop` (`machine_spin`, `travel_plane`, `win_money`): loop until a matching `Stop_<name>` event; `Stop_conveyor_belt_loop` no-op; fade 1.6 s for `travel_plane` is optional. Keep at most one instance per event name; starting a running loop again: Unknown (restart is a safe guess).
4. **(c) Music loop with volume:** music events (+ alias table s.2) start the first sting/main file with loop of the main bed; `Stop_Music` stops. Mutual exclusion with other music. Ambience: `ambience_loop` beds with `Stop_Environments`, mutual exclusion; optional sweetener timer (interval, random pick, volume spread). Volume: Sfx slider `soundlevel/1000` applies to sfx and button group; `musiclevel/1000` to music; `ambientlevel/1000` to environments; `soundoff` -> master 0; apply at current-user change, live on slider messages (hook `BSGSet*Level` in InputWidgets.cpp:643), and in `ToggleSoundMute`. Default levels 0.75/0.65/0.5 when no user.
5. **Focus / pause:** wire `World::setForeground` and the factory `PauseGame/ResumeGame` natives (s.5).
6. **(d) Cross-fade:** fade out the old music and fade in the new over the new arrangement's `MasterModeFadeTime` (table in s.3; which side's time governs is Unknown, so use the new one); mutual exclusion triggers it.
7. **(e) CADI (optional, probably not worth it):** timeline/sting-then-layers handover and quantised starts; requires decoding the CAD arrangement clip positions. Recommend skipping.
8. **Assets:** read `cadi/audio/*.ogg` from Reforged (or a dev-extracted copy). For vanilla-only installs the engine would need CAD extraction (Unknown format of the table) or a one-time extraction tool.

## 10. CADI runtime behaviour (from `CadiApi.dll` and the CAD file)

Sources: `CadiApi.dll` from the Windows install decompiled to `re/cadi/` (Ghidra; image base 0x10000000), the 11,861,719-byte CAD, and `docs/re/audio-music-clips.tsv` (this section's data table: every music event -> arrangement, fades, tempo). The Windows exe `chocolatier-decadence.exe` is Steam-DRM wrapped (`.bind` section, `.text` does not disassemble; Ghidra found 5 functions), so its code is not readable; everything about the exe is from strings.

### 10.1 The DLL API (facts)
* Exports `CadiInit(const char* dataFolder)`, `CadiEvent(const char* name, double p0, double p1, ...)` (0x10001aa0), `CadiEvent_F(const char* name, float p0)` (0x10001c50, widens the float to a double and calls `CadiEvent`), `CadiShutdown`.
* `CadiInit` (0x100015e0): creates the project container, enumerates `<folder>\*.CAD`, opens each (name with the extension replaced by `.xml` is also tried for the symbol table), builds the sound system object, then the whole project. Errors printed: "Failed to create file mapping for CAD file", "Failed to open CAD file". The CAD is memory-mapped.
* `CadiEvent` order: (1) if the system is not initialised, nothing. (2) name == `"Pause"` (exact, case-sensitive, bytewise compare including the terminator): call the sound-system's slot +0xc. (3) name == `"Unpause"`: slot +8. (4) otherwise look the name up; if found, store the extra `double` varargs as the event's live parameters (one per Parameter in the event's ParameterList, in order, narrowed to float), then call `Play(-1,-1)` (-1 = "now") on the found object. All of it under one critical section (`0x10091d30`). Unknown name: nothing happens, no log.
* Pause/Unpause are the output stream: the system object (vftable 0x100696b8) slot +8 is `IDirectSoundBuffer::Play(0,0,DSBPLAY_LOOPING)` and slot +0xc is `IDirectSoundBuffer::Stop()` on the one looping DirectSound output buffer (the same slot is called from `CadiShutdown`). So CADI Pause freezes the whole mix output; Unpause resumes it. Inference: the mixer's buffer cursor is where it stopped, so music resumes mid-note; events sent while paused are queued into the graph and are heard on resume (not verified).

### 10.2 Q1 Event name matching: EXACT, case-sensitive, by hash (fact)
* `CadiEvent` builds a `Spin::cString` from the name; its constructor (0x10001440) stores `hash = FUN_10025930(name)`. A name beginning `"0x"` is parsed as a hex hash directly. Otherwise the hash is Paul Hsieh's SuperFastHash over the raw bytes (seed = length; signed-char tails; the standard avalanche), 32 bit. Lookup (0x10016c80 -> `0x10016de0`) is a map keyed by that 32-bit hash; on a miss the object is loaded lazily. The found object is down-cast to `Spin::cSound`; if the cast fails nothing plays. There is no prefix, no case folding, no alias.

### 10.6 Q2/Q5 Fades, retrigger, exclusion, gain
* **Which fade time (partly):** the ArrangementClip carries both `MasterModeFadeTime` and `SourceModeFadeTime` (and the Arrangement object itself carries another pair; the s.3 table lists the arrangement's). The DLL names the roles "master" (the object being faded/started by the event, inference) and "source" (the thing it replaces, inference); I did not trace the fade code. For a switch to a clip, the clip-level values are the editor-authored ones; they are in `audio-music-clips.tsv`. Many clips have no `SourceModeFadeTime` (blank = default, value unknown). Reasonable implementation rule (inference, flagged): outgoing music fades out over the incoming clip's `source_fade_ms`, the incoming fades in over its `master_fade_ms`, overlapping, with a 1000 ms default when blank. Mark as a decision.
* **Retrigger (facts about selectors only):** the Mixer has `MutualExclusionEnabled` (Music, Environments mixers: 26 mixers flagged). A `cRandomSelector` (every one-shot variant group and `launch`) picks a random child, never the child it picked last time (if more than one child), and **does not start the pick if that child is still playing** (child slot +0x20 test at 0x10019820). Retrigger of an already-playing music arrangement/environment: Unknown (the mutual exclusion code was not traced); safest implementation is "ignore if already the current music/ambience" (inference, not verified; Lua repeats `main_menu` after Options/Help always preceded by `Stop_Music`, so the case is rare).
* **Volume events:** `Music Volume` etc. are `Arrangement`s in the Events mixer with one live `Parameter` and one automation track (`AutomationObject/Target` = the `Music`/`Sfx`/`Environments` channel, `AutomationController` = `Volume`). `CadiEvent(name, level)` stores `level` (0..1) in the parameter and plays the arrangement, so the channel's Volume is set to `level` through the automation. The 0.3125/0.4875/0.5625 points are stored defaults. Whether the value replaces the stored channel gain (root: Music 0.717, Sfx 0.806, Environments 1.423) or multiplies it: Unknown. The most direct reading is replace (automation controller writes the property), which gives gain = per-mille/1000 with no curve (linear); the engine should use gain = level (inference). Per-event and per-track `Volume` values (e.g. `launch` 0.416, `choco_making_game` 1.353) are mixer-channel gains in the same linear domain (>1 allowed) and multiply down the graph (inference).
* **`VolumeVaryMin/Max`, `PanVaryMin/Max`** are properties of the Randomizer node (DLL strings; the CAD uses VolumeVaryMin 0.135-0.255 on environments). The formula is Unknown; reading: a random gain offset of up to that size per play.
* **Q6 `launch` (fact):** `launch` -> Delay (Immediate) -> Envelope -> Repeater -> **RandomSelector** over 13 children (`launch_base_1..3`, `launch_gears_1..2`, `launch_pop_1..5`, `base`, `gears`, `pop`). One random child per trigger, never the same as last time, and not started if that child is still playing. So **the three layers do NOT play together**; one sound plays.

### 10.7 Q7 Options Cancel, factory quit while paused
* **Options Cancel (fact):** the Options dialog (`ui/ui_options.lua`) has only an `ok` button with `default=true, cancel=true`; the Escape key therefore runs `okFunction` = `SaveVolumes()` then `PopModal`. There is no revert path. Slider moves apply live: `TOptions::OnMessage` (Mac 0x2d98c) calls `BSGSetAmbientLevel/MusicLevel/SoundLevel` from the slider value; the per-mille prefs are only written by `TOptions::SaveVolumes` (0x2d678) on OK/Esc. `~TOptions` (0x2d192) does nothing. So levels are always saved when the dialog closes (Reforged's `ui_options.lua:16` is the same). Engine: no snapshot/restore.
* **Factory quit while paused (fact for Mac, inference for Windows):** `ChocolateFactory::PauseGame` (0x8384) calls `BSGSoundPause()` only when the game state field (`this+100`) is non-zero, i.e. after the game started; `ResumeGame` (0xc82c) calls `BSGSoundUnpause()`. The destructors (0x8808/0x8b5c) and the coffee equivalent contain no sound call. The pause dialog (`ui/game_pause.lua`) has only an OK button (`ResumeGame`), and Esc/`ToggleForeground` call `PauseGame("game_paused")`. So there is no in-game quit from the paused state; a factory destroyed while paused (app close) leaves the `gSoundPaused` flag set but the process ends. In the engine, a factory window destroyed while paused (e.g. a debug exit) should call Unpause itself. Mac `BSGSoundPause` also sends the CADI event `Pause` only on a transition, so a second Pause is a no-op.

### 10.9 Q9 CAD container directory (fact; verified)
Little-endian layout of `CADI_Choc3_Adam  FINAL.CAD`:
* offset 0x00: 8 bytes zero; 0x08: u32 = key of the symbol-table entry (0xddfefdc8); 0x0c: u32 entry count (177); 0x10..0x1f zero.
* 0x20: 177 entries of 16 bytes: `u64 key` (the upper 32 bits are zero; the key is the 32-bit SuperFastHash (s.10.2) of the resource's path string, ascending order), `u32 size`, `u32 offset` (absolute file offset). The table ends at 0xb30, exactly the offset of the first Ogg. Entry data are stored back to back with no gaps (the sum of sizes reaches the file end 11,861,719).

The key of every directory entry (including the project XML) is the hash of one of those `Key` strings, which gives each file its original authoring path and thus its name (the basename). **Q2. Whose is the typing sound?**
* Fact: it is `TCustomTextEdit::OnChar`-path code in `re/mac/decomp/TCustomTextEdit.c`. The constructor (about line 47) registers `sfx/sfx_typing_01..04.ogg?group=1000` in the object's `TAssetMap`; the key handler (about line 285) first calls `TTextEdit::KeyHit`, and if the key was accepted it picks `RandDouble * 4 + 1` (an int 1..4), formats `sfx/sfx_typing_%02d.ogg?group=1000`, fetches the sound from the asset map and calls `TSound::Play`. It does not play when `KeyHit` rejects the key or when the widthlimited check fails.
* Fact: `TCustomTextEdit` derives from `TTextEdit` (its constructor calls `TTextEdit::TTextEdit`), and its source header is `customtextedit.h` (see `fonts-and-text.md` section 4). The Playground base is `TTextEdit`, which has no sound. The sound belongs to the derived class, which also holds the Chocolatier-specific `onkey` Lua callback, `enablewindow` and `clearinitial` keys.
* Inference: `TCustomTextEdit` is game code (Chocolatier 3 / Big Splash), not the SDK: the `Custom` prefix, the hard-coded game asset paths `sfx/sfx_typing_*` (the files exist only in the Chocolatier 3 data, `re/choc3/pfp_extracted/sfx/`), and the absence of the class from the other titles all point that way. The binary does not label SDK versus game code, so this is not proven.
* Fact: Chocolatier 2 does not have it. No `sfx_typing` file exists in the Chocolatier 2 Windows install's `assets/`, `re/choc2/strings.tsv` has no such string, and `re/choc2/classes.txt` lists `TTextEdit` but no `TCustomTextEdit`. So Chocolatier 2's text field is a plain `TTextEdit` with no key sound.
* Fact: Chocolatier 1 has typing sounds with different names (`audio/sfx/typing_01..05.ogg`, in `re/choc1/strings.tsv` and `assets.pfp` in the Chocolatier 1 Windows install), and its classes list has no `TCustomTextEdit` either. Whether Chocolatier 1 plays them from its text edit was not traced (unknown).
* Consequence (inference): the typing sound should live with Chocolatier 3 game code, not in shared `ui/widgets`, if the layering is to follow the originals; Chocolatier 2 must not play it.
